# Source-owned through-all UI settings

The internal component constructs four known part Definition scalars without forwarding a saved UI word. It adds no public writer admission.

`ReadThruUi(document, link, definition)` uses the actual validated source link and returns `PartUiInput(HlrQualityCode, DisplayGrid, DefaultCommandGroup)`. `MakeThruUi` composes that input with the existing source owner, part settings, configuration intent, camera, empty-manager and line-table inputs. Quality codes zero/one and display mode three are the bounded profile. The grid choice is Boolean. Command group is `features` or explicit `none`; other groups refuse.

The part context type derives from the native confirmation rule. Features maps to its pinned installed command-group vocabulary; resource text and saved words are not writer dependencies. Previous default callers remain byte-identical.

`CountPartEnvs` verifies the stored count, row structure and actual environment class/schema. It does not reconstruct saved usernames, primary/secondary splitter bodies or window placement. Native save may capture a current-user row before counting, and load can filter entries. Do not replace this state with a fixed presence flag or count one. Both disclosed sources still retain the source environment as an unresolved owner; complete-source admission refuses.

Verification: 92 host processes, 48 SDK refusals, two disclosed source cases, eight authored setting combinations, 70 independent fragment re-emissions, unchanged old Definition/owner bytes and two old container pairs. Scoped static/donor checks pass. No native process, D03 or original held-out input was used. Remaining frontiers: two Definition and twenty-nine CMgr.
