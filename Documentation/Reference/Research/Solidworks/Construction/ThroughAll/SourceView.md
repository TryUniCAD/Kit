# Through-all source document camera

This internal component follows the source configuration-intent and actual nested-member components. It builds the proven orientation/pan/scale owners while complete source conversion remains refused.

`ReadThruView(document, link, definition)` reads the concrete version-19000 ordinary part Definition paired by the caller with the same complete source archive. It retains the current complete-source and actual root identity checks. The result is the existing immutable `ViewInput`, with a right-handed orthonormal orientation matrix, three finite native pan coordinates and a positive scale.

`MakeThruView(owner_input, settings, config_intent, view_input)` returns the existing `ThruConfigGraph`. The actual part/system/configuration and through-all geometry come from `MakeThruConfig`. The shared view constructor supplies two fresh Definition transform records. This returns an incomplete internal component, not a complete native part or an accepted public conversion.

The lower `ReadViewPair` and `CheckViewRep` require canonical source matrix presence and zero perspective flags. They reject shear/reflection, unknown fields, unrepresented affine state and numeric errors. They do not rewrite existing source graphs. Existing default and camera constructors remain unchanged.

The frozen external replay verifies source, tools and disclosed-input hashes, then performs normal SDK source reads, deterministic no-runtime-I/O construction, independent linked readback, exact previous-output comparisons and negative SDK processes. It also records every remaining Definition/CMgr owner. Per-user windows, unknown UI state and full source/native qualification remain separate requirements.
