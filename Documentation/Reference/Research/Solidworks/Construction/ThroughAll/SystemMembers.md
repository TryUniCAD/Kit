# Through-all system-member component

This private internal layer follows the source configuration-intent component. It preserves the known note-pair/light semantics from the three disclosed ordinary through-all sources. Complete source conversion remains refused.

`ReadThruMembers(document, link)` consumes the complete ordinary source document and the same source's existing typed `NativeLink`. It returns `MemberPlan`: an immutable `MemberInput` plus source correspondence IDs. The source is retained unchanged. The exact source profile contains one ambient and three directional lights plus an empty reciprocal note pair.

`AttachMembers(system, input, target, allocator)` accepts a freshly constructed one-configuration `PartSystem` with actual empty cabinet/environment lists. It returns `MemberGraph` with the actual generated note and light nodes. Each explicit light carries its names, three coefficients, COLORREF word, keep-in-scene/render/display settings, directional vector/softness when applicable and precise creation instant. Notes carry two explicit regular captions and independent instants. The constructor derives IDs, ordering, counts and actual partner/owner references; the existing archive executors derive every wire tag and map.

The lower constructor uses an explicit ordered nonempty scene and has no universal four-light rule. External identifiers may repeat. The native direction setter copies three components without normalization. Only model-space, unsuppressed source lights and empty user-property state are in this source projection. Other light families, source suppression/coordinates and populated notes/properties refuse. Native uniqueness, registration, annotation-view lifecycle and generic source feature state remain unqualified.

The nested revision validation supports only the actual source-proven cabinet/environment paths. It never rewrites a member's owner to the model merely to satisfy a log check. Header components derive `f48` from actual new nodes and retain the declared event sequence. Complete source chronology/reference-time joins are separate requirements.

The frozen external method verifies source/tools/input hashes before native-source access, runs real SDK generation and linked readback in fresh processes with runtime I/O denied, then preserves full-source refusal. It compares old ambient/default outputs and refuses malformed ownership and fields. Native execution and original held-out acceptance are separate root-owned steps, not part of this component's result.
