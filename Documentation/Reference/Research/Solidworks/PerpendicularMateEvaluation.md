# Perpendicular evaluation workflow

The [method record](../../../../re/solidworks/records/PerpendicularMateBlindMethod2026.md) and [receipt](../../../../re/solidworks/measurements/2026/SdkPerpendicularBlindMethod01.json) describe PR #121's private blind evaluation of one ordinary perpendicular mate. Native hidden sources were locked before constructor work; no hidden values are used to prepare or tune the method.

Freeze the full source/tool/neutral-prediction/comparison closure first. `VerifyPerpendicularFreeze.py` then checks every fingerprint and reproduces the independently committed disclosed file identities twice in the actual guest runtime. Root reviews that runtime record and releases one opaque slot. The standalone entrypoints support isolated Python invocation and reject host extraction/evaluation before any private input access.

`PreparePerpendicularSlot.py` checks the original combined neutral-specification hash, extracts the requested case on the guest fixed drive, and locks its canonical digest, request, independent prediction and expected trees before source native observations are opened. `EvaluatePerpendicularSlot.py` separates guarded generation, each native phase and final comparison. A trailing disclosed control is run independently even when a case fails. Root owns all VM execution; these tools never terminate an unrelated process or licensing service.

The [runtime gotcha](../../../Gotchas/Conversion/Solidworks/Oracle/Assembly/RuntimeArithmeticChangesArchiveDigests.md) explains why the host and guest have separate exact preflight commitments. Generator math and format rules remain unchanged. Native pass, typed decoding, strict paired equivalence and public writing are separate facts; this method does not register public perpendicular writing.
