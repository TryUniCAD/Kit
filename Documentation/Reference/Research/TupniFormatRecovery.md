# Tupni-guided native format recovery

The [Tupni playbook](../../../re/Playbook/Tupni.md) describes the reusable
procedure for recovering CAD archive rules from native loader observations.
It defines the capture boundary, trace provenance, field/record/constraint
workflow, corpus generalization and promotion gates.

The [SOLIDWORKS 2026 ledger](../../../re/solidworks/records/Tupni2026.md)
records the first application, including its pre-adoption baseline and pending
capture obligations. It is updated with actual evidence as work progresses.
Static dataflow, native API hooks, instruction taint and Kit codec traces retain
separate authority labels. Tool setup alone does not establish format recovery
or a measured improvement.

The [radial training procedure](../../Changes/Solidworks/Inspection/Sketches/SolidworksRadialTrainingObservations.md)
adds bounded lifecycle observations for matched radius/diameter and annulus inputs.
It reuses the retained oracle controller and preserves the locked held-out inputs.
Mapped instruction checks, capture qualification and native output acceptance remain separate results.
The [observation contract](../../../re/solidworks/records/RadialTrainingObservation2026.md)
defines the source, process, control and trace requirements.

Read the [CAD success criteria](../Operations/CadSuccessCriteria.md) before using
this method for a writer. Trace-derived values remain research data. Production
serialization needs model-derived rules and complete native acceptance.
