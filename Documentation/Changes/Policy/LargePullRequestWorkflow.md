# Large pull request workflow

Large PRs have standing authorization for targeted local testing and parallel
implementation or research. Use one owner for a shared vendor oracle and close
completed Hopper documents after recording evidence.

Begin configured review when the requested work and its pre-review acceptance
evidence are complete. The current head still needs every configured reviewer's
successful reports and approval for readiness. PR CI and queue acceptance run
on their required revisions.

See [standard PR practice](../../../.agents/skills/standard-pr-practice/SKILL.md#large-pull-requests)
for scope, test policy, and review timing. The policy uses the existing
[PR size labels](../../../.github/workflows/PullRequestSize.yml). The guidance links to the active size workflow and testing rules. Full CI
verification follows publication.
