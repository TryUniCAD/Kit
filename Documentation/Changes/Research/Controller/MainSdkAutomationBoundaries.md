# Automation boundaries on the main SDK

The initial automation-only revision used main’s existing SDK. The subsequent phase commits restore the saved-file SOLIDWORKS and Fusion decoder changes, native writer work and their public qualification guards from the original PR #94 source.

Research readers keep `kit.research_read_status: unqualified` in neutral metadata. The restored public native writers enforce that marker. Fusion retains its explicit opt-in partial retry and records the strict rejection.

Generic `inference.fields`, `inference.paired-gap`, `inference.rescan` and scheduling remain available. Field search loads NumPy when field inference runs. Inference receipts retain `semantic_qualification: unverified`, `native_acceptance: not_established` and `portable_complete: false`.

The restored archive gate exercises the fixed native profiles. The P04 through-all assessment parks until its continuation binds authenticated application-grid evidence. Submitted reports cannot assert a `native_grid`, `continued_from_receipt` or `grid_from_receipt` field.

Original corpus, recipe, capture, source revision and receipt pins remain unchanged. New operations need a new immutable tool version and job identity because the SDK and tool source inventories differ. Historical source graphs and private reports stay attached to their exact original revisions. Reintroducing captured files on a shortened history does not preserve `GitSnapshot` introduction ancestry. The [sealed history binding](../CaptureHistoryBinding.md) checks unchanged current inputs while evaluating original provenance on the preserved graph, with current full-tree alias checks retained.

The test suite covers generic assessments, pinned rescans, tampered inputs, forged native proof claims and the restored native archive boundaries. The phase register records source-bound verification and the remaining native qualification criteria.
