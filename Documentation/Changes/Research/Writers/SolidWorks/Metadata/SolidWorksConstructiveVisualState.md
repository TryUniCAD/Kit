# Constructive standalone SOLIDWORKS visual state

A12 now has a constructive generation-19000 serializer for the optional `ThirdPtyStore/VisualStates` member. It builds a typed standalone configuration relationship, one representation, explicit component owners, material attributes and display attributes. The research package writer accepts this state through optional `PackageState.Visualization`; omitting it retains the existing package bytes and member roster. This is offline construction progress. Native open, editable geometry, rebuild, save and fresh reopen acceptance remain pending. No production writer or capability is registered.

[Model](../../../../../../re/solidworks/WriterResearch/VisualState/VisualStateModel.py), [serializer](../../../../../../re/solidworks/WriterResearch/VisualState/VisualStateArchive.py), [readback](../../../../../../re/solidworks/WriterResearch/VisualState/VisualStateReadback.py), [package binding](../../../../../../re/solidworks/WriterResearch/VisualState/VisualStatePackage.py), [process verifier](../../../../../../re/solidworks/WriterResearch/VisualState/VerifyVisualState.py).

## Supported grammar and inputs

The constructor takes an authored configuration ID, representation ID, nonempty wide name and an ordered owner collection. The first owner is the standalone holder with an explicit appearance. Remaining owners carry feature IDs and creation clocks with inherited appearance. Each owner has a caller-selected Boolean visibility and the proven ordinary display settings `(6,1,0)`. The standalone package binding requires exactly the generated profile, Origin and three principal planes, joined to their own header creation logs. Representation IDs, feature IDs, material IDs, visibility choices, counts and archive references are generated from these inputs. None are fitted to the saved P03 object numbers or row bytes.

The reader consumes every field, verifies pointer kinds and object ownership, validates the complete material and DSPBR body through typed re-encoding, and requires exact EOF. Material bump and displacement are normalized only to their written float32 representation. It refuses unsupported display branches, invalid locator variants, duplicate owners and noncanonical attribute sharing.

## Offline verification

`VerifyVisualState.py --replay-corpus` reads the eight sealed P03 controls through the existing receipt-checked capture intake at `466dcb172dfa3803463e07ccde963ba01671d200`. Each 1789-byte member is decoded and reconstructed exactly. The corpus is an inverse check; its bytes are never construction templates.

`VerifyVisualState.py --fixture-context - --visual-state '<JSON>' --candidate <unused-path.SLDPRT>` reads the existing independently authored fixture context from standard input. The visual JSON requires `representation_id`, `name` and `visibility`, with explicit Boolean keys `holder`, `26`, `5`, `2`, `3`, `4` for that fixture. It first verifies the original complete fresh Boss, builds the same package with the new member, compares every former member byte-for-byte, rereads the whole visual state, and publishes through the existing atomic no-replace operation. With previews, the package has 33 members. Other research callers can construct `VisualState` directly and bind it through `PackageState.Visualization`.

The fixture's saved package code 4 and header license type 2 are licensing-related document classifications inherited from the existing research context, not visual settings or evidence of a current application entitlement. The internal package getter and the separate header classification are documented in [eModel saved package metadata](SolidWorksEModelLicense.md). That evidence explicitly leaves fresh neutral-first classification dependent on an approved native save context. Offline generation does not establish that context. A candidate using those fixture values must remain outside native dispatch until the actual authorized save classification is established; no authenticity or licensing check may be bypassed or forged.

[Process checks](../../../../../../tests/Research/Archives/VisualState) cover independent representation and appearance IDs, a long Unicode name, zero through twenty feature owners, dynamic attribute sharing, malformed streams and unsupported fields. Full-package checks run with native input reads and subprocess launches forbidden. They check unchanged geometry and metadata, explicit visibility and feature clocks, rejection of foreign configurations, owners, clocks, appearances and stale allocator state, and preservation of an existing publication destination. The existing fresh Boss process suite checks caller compatibility when the optional state is absent.

## Native proof still required

The sole campaign oracle must open an independently generated candidate in a healthy controlled SOLIDWORKS session, measure the live feature tree, one solid, bounds, volume and centroid, change each driving dimension independently, rebuild, restore, save, close and reopen in a fresh process. It must inspect the authored display state, owner visibility and material identity before and after native save. A successful byte inverse is not that proof. The first-save live profile visibility and historical template/material allocation lifecycle remain distinct research questions; this constructor makes explicit settings and reuses an already assigned caller appearance rather than claiming those defaults are solved. Any promotion remains subject to the campaign criteria and independent native measurements.
