# File stall experiments

A file run records the unresolved dimensions, features or stream ranges that define its next research question in `FileStall.json`. With `--advisor codex`, the file stage can spend one call from the run budget on a hypothesis and controlled experiment. Codex defaults to `gpt-6.2-sol` at medium reasoning. The provider sees a predefined description of the gap and available experiments. File names, feature names, hashes, measured values, byte ranges and CAD contents stay in the local run directory. `FileAdvice/Request.json` shows the packet and its local evidence hashes. A proposal cannot establish a verified rule.

For ambiguous extrusion depth, the decoder tries shifting the complete signed mirror layout inside the owning feature. When bounded searches find no match, that outcome informs the question. A provider can choose which registered depth edit to replay first. The file runner also replays the other applicable edit, and runs both deterministically when advice is disabled or unavailable. It reads separate baseline and edited discovery saves, checks that only the declared dimension changed, binds both native scalars to recorded reopen measurements, then searches the input for the measured copy offsets. A match is a candidate for further validation.

```sh
kit run --root . solidworks --input wheel.SLDPRT --directory /tmp/wheel-advice --advisor codex --auth login --advice-calls 1
```

On the V8 turbine wheel the shifted-layout probe found no match for any of seven extrusion features. The P03 boss edit changed from 10 to 12 mm and preserved five signed copies. The P04 cut edit changed from 4 to 5 mm and preserved four. Neither pattern matched the unresolved target fields. Other gap types can receive a research suggestion, but only the two depth experiments have executable file-level replays. The live hosted model has not been verified for this path.
