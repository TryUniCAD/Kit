# Analytic solid reader generation

A standalone ASM snapshot with one closed, untrimmed spherical or ring-toroidal face can produce a runnable research reader. The decoder follows the body, lump, shell, face and surface references, applies the body placement and selects the corresponding analytic equations. The generated program reads new input bytes through Kit's geometry decoder. It reports radii, center, bounds, surface area, volume and topology counts. It accepts translated, rotated and uniformly scaled placements that satisfy its frame checks.

Use `kit run --root . auto --input part.smb --directory /tmp/solid-run`. Inspect `Input-raw-structure.json` for the recovered properties and native comparisons. When the input itself and the available registered controls match their reopened Fusion observations, and the corpus includes at least two distinct volumes, the run writes `Reader.patch`. The patch adds a research script at the path in `Input-reader-patch.json`. Apply it on the reported base revision and run it with the project's Python and `PYTHONPATH=src:re/automation`.

Two sphere snapshots and five torus snapshots replayed against archived native measurements. The comparisons cover center, axis-aligned bounds, area, volume, and face, edge and vertex counts. These files are controls from the registered round-body study. Replaying them does not establish generalization to another authoring lineage, or recover the parent document's parametric history. The equations and source template are predefined. No file offsets, measured dimensions or vendor bytes are embedded in the generated source.
