# Maintain the empty-owner composition process boundary

The complete compatibility suite now runs the actual three-request
`ComposeEmptyOwnersPart.py` command in a fresh process. It derives the `Default`
request from the committed authored presentation JSON, supplies explicit empty
appearance intent, and uses the committed property request from its pinned
checkout. It needs no private CAD capture.

The test reuses `OpenLegacy` to provision clean exact reader and property
worktrees from the existing research checkout. The ordinary test planner,
research preparation, shards and completeness report collect this case under
`tests/CliResearch/EmptyOwners/CompositionTests.py`. Both dependency commits
remain enforced by the real command.

The first maintained run exposed a property-module import that redirected the
caller's sketch-helper lookup. The unchanged module-identity guard refused
output. The composition now restores its caller's search path around that
import and checks the origins of the property verifier and artifact helper.
[Search-path collision](../../../Gotchas/Research/Writers/SolidworksPropertyImportChangesCallerSearchPath.md)

The smoke verifies the emitted archive receipt, fourteen-member boundary,
typed owner reports, linked depth and Top identity. It retains the ordinary
Definition and default public refusals and the model-only `create` to `join`
difference. An integer cut-owner request must exit 1 before creating output.
Compressed archive identity is bound to the process receipt rather than one
platform's compression backend.

This is offline process coverage. It does not establish native acceptance,
ordinary source admission or full-source preservation. See the
[usage and recorded verification](../../../../re/solidworks/records/EmptyOwnersPartComposition.md#maintained-process-coverage).
