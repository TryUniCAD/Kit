# SOLIDWORKS Top annotation candidate

The SOLIDWORKS research writer generates a complete blind-boss part with one configuration-owned orthographic Top annotation view from persisted neutral JSON. Run `python re/solidworks/WriterResearch/ComposeTopAnnotation.py --request Request.json --native-locator C:\KitA12bResearch\reconstruction.SLDPRT --written-at 1785626030 --scratch Scratch` to create the candidate and custody manifest. The native locator stem must match the name in the neutral document. [Request schema and field ownership](../../../../re/solidworks/WriterResearch/TopAnnotationCandidate.md)

Run `python re/solidworks/WriterResearch/VerifyTopAnnotationCandidate.py --scratch Replay` to create the request from the existing four-line neutral example. The replay generates identical candidate bytes in two fresh Python processes. The paired plain and annotated archives differ in exactly the configuration and linked resolved-feature streams. Both read as one solid with a 14.31 mm driving depth and 7,584.3 mm³ volume. The typed readbacks match after accounting for the two added archive slots. [Offline candidate evidence](../../../../re/solidworks/measurements/2026/VendorBlindBossTopAnnotationCandidate.json)

The request covers the default Top frame of the sole active configuration. Custom poses, annotation pointers, other view roles, visibility overrides, and other presentation intent require additional evidence. Native measurement and production qualification use separate gates.
