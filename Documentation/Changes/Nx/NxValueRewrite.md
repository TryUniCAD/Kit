# The token family is re-emitted from decoded values

## Behaviour

`ObjectSection.RewriteValues` rewrites the words of every `02 02` record family by
decoding them and writing them back through the encoders:

- a `50 <handle> 00 00` word is read with `ReadValueWord` and written from the handle
- a `30 ??` or `2f ??` float word is read with `ReadFloatWord` and written with
  `FloatWord`

`nx.author_sections` runs it after the record, reference and lane passes. The bytes
written now come from the encoders rather than from the source buffer.

## Verification

Byte provenance is unchanged, because the same values are re-emitted:

```text
part            section 0 differing   payload identical
empty.prt                        340             99.00%
multi.prt                        340             99.02%
var_blank.prt                    341             99.01%
const_box60.prt                  344             99.15%
dim40.prt                        344             99.15%
```

Writing and loading all five in NX 2506:

```text
v2_empty.prt bodies 0   v2_multi.prt bodies 0   v2_var_blank.prt bodies 0
v2_const_box60.prt bodies 1   v2_dim40.prt bodies 1
```

The view records are covered too, and decode to view geometry rather than labels:

```text
184 byte Front view    +-508.0  +-2639.645431  +-2688.083332  0.755928946  1145.664032  0.013962634
```

That is a set of mirrored extents, a unit scale near `0.7559`, and two small factors, so the
matrix and extents are the same float encoding as the token family.

`TestNxValues` checks that a record round-trips through `RewriteWordRun` unchanged.

## Limits

- Provenance does not move, because the pass re-emits the source values. It gains the
  derivation path, not new generated bytes; emitting chosen display values would move
  it and is not enabled.
- The pass is byte-safe by construction: a word is only replaced when re-encoding it
  reproduces the same bytes, and a value outside the single precision range is skipped.
  That guard was added after an `OverflowError` on a view record stopped a write.
- The first version of this pass encoded the handle as a value instead of re-emitting
  the handle, which corrupted the records: all five parts were refused by NX
  (`OPEN_FAILED`). The bug was caught by the NX load, not by the byte count.
