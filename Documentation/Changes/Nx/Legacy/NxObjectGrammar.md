# Two root object record families are decoded and re-emitted

## Behaviour

`convert.adapters.nx.ObjectSection` now has grammars for the two largest record
families in the root object section, so those records can be produced from fields
rather than copied:

```text
AttributeRecord(KeyText, ValueText, Ordinal, Marker)
  01 02 04 <len(key)+2> key 00  01 02 04 <len(value)+2> value 00  <ordinal> <marker>

PairRecord(First, Second)
  fixed 30 byte frame  <token First>  ff x 6  <token Second>  ff x 8
```

`ParseAttribute` and `ParsePair` read the same records back, and `RegToken` emits the
registry token encoding: values up to `0x7f` in one byte, larger values behind a
`0x80` prefix.

## Verification

Every record of both families round-trips byte for byte in all three body-less
fixtures:

```text
part            attributes  pairs  decoded of 214
empty.prt        77 / 77    15 / 15          92
multi.prt        77 / 77    15 / 15          92
var_blank.prt    77 / 77    15 / 15          92
```

So 92 of the 214 records, 43 percent, can now be re-emitted from their fields.

`TestNxGrammar` checks both grammars, the token encoding, the range guards and the
malformed-record rejections.

## Emitter

`RewriteRecords(SectionBody)` rebuilds every record of the two decoded families with
values Kit assigns: attribute ordinals count up from one, and pair ids are labelled
sequentially with the token width preserved. `nx.author_sections` runs it on section 0
after the head record is handled.

```text
part            rewritten records   refs   tokens   lanes   section 0 differing
empty.prt                      89     12       21      30                       340
multi.prt                      89     12       21      30                       340
var_blank.prt                  89     12       21      30                       341
const_box60.prt                89     12       21      30                       340
dim40.prt                      89     12       21      30                       340
```

`RelabelRefs` assigns new seven byte references to the shared values of the instance
records in every shape and in both class tags — `02 02 ?? 4d` in a body-less part and
`02 02 ?? 5b` in a part with a body —, not only the three group one: the
value runs are found by skipping zero padding to the next `30` or `b0` tag byte and
taking the seven bytes after it, and each value is replaced at every occurrence so no
stale duplicate is left behind. It finds 12 value runs with six distinct values in a
body-less part and 12 in `const_box60`, `dim40` and `var_datum`, whose instance records
use the `5b` tag and a `f0 08` frame.

Section 0 was previously identical to the source in every byte. It now carries 340
generated bytes for a body-less part and 214 for `const_box60`, and payload identity
moves from 99.97 to 99.00 and 99.46 percent respectively. The lane family is described
in [the lane record change](NxLaneRecord.md). All five parts still load:

```text
rw_empty.prt        bodies 0     rw_const_box60.prt  bodies 1
rw_multi.prt        bodies 0     rw_dim40.prt        bodies 1
rw_var_blank.prt    bodies 0
```

## Limits

- The remaining 122 records across the other families (for example `02 02 41 4d`
  and `02 02 41 00`) are not decoded.
- The ordinals and the paired ids do not have to be copied. Rewriting them across
  the whole family is accepted:

  ```text
  all 15 pair records with First and Second swapped        loads
  14 pair records with both ids incremented by one         loads
  all 77 attribute ordinals incremented by one             loads
  all 77 attribute ordinals set to the same value 0x40     loads
  ```

  so for these two families NX treats the values as labels and an emitter may assign
  its own.

- The `02 02 41 4d` instance-id family is checked across records rather than within
  one. `RelabelRefs` handles the case where the shared value sits in the three group
  48 byte shape; the value is replaced at every occurrence. Changing a value byte in
  one record loads, replacing the whole value run in one record is refused, and
  replacing a value consistently at every one of its occurrences loads:

  ```text
  a5 00 f7 77 4c 1f c5  ->  11 22 33 44 55 66 77   at 8 places   loads
  a4 a0 17 42 b2 81 da  ->  88 99 aa bb cc dd ee   at 4 places   loads
  ```

  so the values are shared references and relabelling is allowed; what is missing is
  the padding rule, since the tail is 6, 13 and 27 bytes for zero, one and three
  values and the zero padding moves around the value list.

- The `02 02 41 00` family's two byte tokens are relabelled by `RelabelTokens`, which
  maps every distinct token value in the family to a label counting from `0x10` and
  rewrites all 21 occurrences consistently. The family's other value bytes, such as
  the fixed point numbers in its longest records, are not touched.
- The remaining records across the other families are not decoded.
- `RewriteRecords` has no unit test: it needs a whole section 0 to exercise, and the
  fixtures are not available to tests, so it is covered by the five NX loads above
  and by byte provenance rather than by an assertion.
- Section 0 is still carried from the source, so no part is written without a source
  document.
