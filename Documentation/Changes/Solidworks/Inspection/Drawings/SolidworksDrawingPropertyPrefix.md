# SOLIDWORKS drawing property-value prefix

The research drawing property constructor now declares `vt` on each generated property document and uses that prefix for its text values. It preserves the neutral values, IDs and name dictionary. It does not change ElementTree's global namespace registry.

The native serializer reuses the supplied SolidWorks property DOM and creates literal `vt` element names. Declaring the same URI under another prefix is sufficient for SDK reading but does not supply that literal binding during native editing. The source rule and the measured failing call interval are recorded in [DrawingPropertyPrefix2026.md](../../../../../re/solidworks/records/DrawingPropertyPrefix2026.md).

Two guarded subprocesses produced identical complete drawings with zero runtime input-file access attempts. Only the property XML changed among seven logical streams, and its expanded XML tree is identical to the previous failed candidate. A host generic-DOM replay reproduced an unbound-prefix parse error for the previous binding and passed for the revised binding; quoted names and markup text also round-tripped through the constructor, serializer and parser. Native save acceptance is pending. The prior corrected-section candidate still failed native SaveAs in an interpretable nine-process trial with healthy controls; it is retained as evidence.

[InspectBlankDrawingPropertyPrefix.py](../../../../../re/tooling/sw2026/InspectBlankDrawingPropertyPrefix.py) verifies the frozen source proof and candidate before actual scale edit, SaveAs and fresh reopen. Supply `--packet-sha256` and `--runner-sha256`; `--verify-only` performs host custody verification. Successful native exit requires the generated case and all controls in ten distinct processes. Additional property types, held-out drawings and production writer admission remain unqualified.
