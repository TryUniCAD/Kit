# Generated scaled drawing oracle

The research preparer `re/tooling/sw2026/PrepareScaledDrawing.py` freezes four separately generated drawing/part pairs for Front, Top, Right and Isometric views. It accepts a complete independently authored neutral job, an exact disclosed source lock and an unused private destination. Each pair is built twice through the original guarded process. The preparer requires identical complete outputs, zero runtime input-file access, exact archive/SDK graph readback, and agreement with independent trigonometric rotations, eight projected corners and analytic rectangular-prism mass properties.

The native observer `re/tooling/sw2026/InspectScaledDrawing.py` reuses the existing typed front-view phase. It brackets the four generated lanes with an unchanged disclosed scaled native control. Each successful lane edits the actual view position, rebuilds, measures its linked child and complete 16-row drawing tree, saves the drawing and checks the edited result in a fresh process. A fully passing batch requires twelve distinct oracle processes, all six lanes, healthy controls, zero errors/warnings/dialogs, immutable inputs and final packet/tool custody. An interpretable generated failure exits 3; healthy controls alone cannot report success.

Prepare a job with schema `kit.sw2026.scaled-drawing-neutral-job.v1` and ordered case names `GeneratedFront`, `GeneratedTop`, `GeneratedRight` and `GeneratedIsometric`. Each case supplies `request` in the existing `DrawingFrontBundleProcess.py` neutral bundle format. Run the preparer with `--corpus`, `--job`, `--job-sha256`, `--output` and `--windows-directory`. The resulting `Trial.json`, `Tools/GuestTools.json` and runner digests pin the native invocation. The observer supports `--verify-only` on the host without importing the Windows COM runtime.

The first discovery preparation used four shifted rectangles, dimensions 17.3×11.9×5.4, 28.7×13.4×9.1, 21.6×18.2×7.3 and 32.1×22.7×11.6 mm, with view scales 0.45, 1.35, 0.7 and 0.9. Eight guarded subprocess builds passed, producing four distinct drawing and part pairs with identical replay output and zero runtime reads. Independent SDK transform and outline checks and host packet verification passed.

All four generated pairs and both pristine brackets passed in twelve distinct processes on SOLIDWORKS 2026 SP05.2. The 1,194 numeric checks include the native geometry, transform and editable view position. Every drawing save returned `[true, 0, 0]`. All four generated derivatives reopened with their edited position, linked part, configuration, measured geometry and sixteen feature rows intact. The SDK recovered each saved view layout. [Controlled native result](../../../../../../re/solidworks/measurements/2026/DrawingScaledViewNative01.json)

This is a bounded research oracle, not a production writer or held-out qualification. It supports the specified four standard orientations, one explicitly scaled view, an unformatted ANSI A landscape sheet and a generated XY-aligned rectangular boss. The native control is a pristine disclosed source. Its child is accepted only at the exact original or matched staged path and with its locked hash; original child bytes are never replaced. Sealed drawing sources remain unopened, and the original blind mapper and all predecessor packets are preserved.
