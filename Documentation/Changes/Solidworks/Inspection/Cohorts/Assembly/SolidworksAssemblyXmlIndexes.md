# SOLIDWORKS generated assembly XML indexes

Set the top-level boolean `include_xml_metadata` to `true` on a research `AssemblyRootProcess.py` request. It builds `swXmlContents/COMPINSTANCETREE` and assembly KeyWords from the constructed graph and gives the generated child its principal-plane and origin KeyWords roles. An empty graph requires an explicit native output file identity. A populated graph accepts direct rigid occurrences of one generated ordinary part and one configuration. The default process profile keeps the earlier assembly and part bytes. [Field rules and exact artifacts](../../../../../../re/solidworks/records/AssemblyInstanceTree2026.md).

`open_document(path, include_brep=False)` validated the generated sibling pair with two definitions, one linked document and three placements, including a 90-degree rotation and two nonzero translations. The linked sketch's archive handle resolved to its actual Front plane. The empty assembly also validated with default open settings. Guarded process comparisons showed zero runtime input data reads, exactly two additional root streams and only a KeyWords change in the child. [Public and process integration](../../../../../../tests/Convert/Solidworks/Research/Assembly/XmlIndexTests.py).

For the populated pair, default geometry loading fails at the generated child's missing Parasolid payload. The reduced profile has scope limits around saved presentation state and assembly topology. Native application measurements cover the earlier binary profile, and the new XML-bearing archives have SDK inspection evidence. The SOLIDWORKS production writer remains disabled.
