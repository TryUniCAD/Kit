# SOLIDWORKS managed plane construction map

PR #121's reference-plane research now traces the concrete mixed-mode core request, geometry and constrained-plane construction route in the pinned SOLIDWORKS 2026 build. It distinguishes actual CIL method bodies from native import thunks, the current three-slot constrained-plane route from the compatibility face-plane route, and a feature-create-version guard from serialized layout changes.

[ManagedConstructionIndex.py](../../../../../re/tooling/sw2026/ManagedConstructionIndex.py) is an offline research tool. Supply the external managed module, its expected SHA-256, explicit `--method` tokens and an output receipt. Optional `--native-module`/`--native-sha256` resolves import thunks to original native exports; `--family-index` lists matching adjacent request types without decoding their method bodies. `--check` verifies an existing receipt without writing it. Use pinned `dnfile==0.18.0`, `dncil==1.0.2` and `pefile==2024.8.26`. The tool returns identities, method flags, hashes and call edges; it emits no vendor code or listings and never executes the target.

The [construction record](../../../../../re/solidworks/records/ReferencePlaneManagedConstruction2026.md) describes exact current/compatibility owners, constructor arguments, owner publication, angle limitations and existing SDK reader reuse. The [receipt](../../../../../re/solidworks/measurements/2026/ReferencePlaneManagedConstruction01.json) pins 33 selected methods and the metadata-only adjacent-family index to the original module SHA/MVID. The [factory-export gotcha](../../../../Gotchas/Conversion/Solidworks/Model/ReferencePlanes/ReferencePlaneFactoryExportIsABaseStub.md) explains why the folded generic model factory did not reveal this active route.

The real-process offline metadata audit and deterministic replay passed. The offset native source packet is unchanged; it remains a source qualification step before writer work. This change adds no writer, modifies no SDK reader, opens no held-out source and makes no native acceptance claim. Runtime API route confirmation, full field classification and generated held-out edit/save/reopen proof remain required.
