# Observe recursive feature names across native save boundaries

The existing generated-part observer records only top-level feature nodes, while source authoring records subfeatures recursively. The new research-only `re/tooling/sw2026/InspectTreeNames.py` uses the same source-side recursive walker and records separate trees immediately after opening, after explicit rebuild, immediately after native save and after a separate fresh-process reopening. It retains load/body/geometry/dimension checks from the frozen shared circle inspector without changing that inspector or any writer dependency.

Run it through the existing external frozen-source job and host-supervisor procedure, with the pinned 2026 oracle hash, before/after controls, unused external output directory and generated case hashes/neutral requests. The job shape matches the circle observer's metadata and case list; the new observer performs two phases per case and introduces no dimension edit. It records each source and saved-file hash, immutable inputs, fresh process identities, dialogs, cleanup and feature diagnostics. A tree observation cannot count as a newly generated output or a new held-out writer prediction.

The walker retains the source tool's bounded `(name, type)` deduplication and sibling traversal limits. It does not establish universal object identity for repeated names/types. Matched traversal can expose child and parent/name differences, but `full_tree_parity`, `native_acceptance` and `heldout_acceptance` remain false until an independent comparison establishes the relevant claim. See the [traversal-depth gotcha](../../../../Gotchas/Conversion/Solidworks/Oracle/FeatureTreeWalkDepth.md).
