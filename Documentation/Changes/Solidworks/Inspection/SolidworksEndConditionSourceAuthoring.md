# Controlled extrusion end-condition source authoring

The existing independent `re/tooling/sw2026/AuthorCurves.py` oracle now also accepts `EndConditionSpecs.json`. This separate source family has twelve discovery cases, four held-out cases and two independently authored controls. It varies forward and reversed blind, mid-plane and two-direction blind bosses. Discovery ladders keep the rectangular section fixed while varying depths and reversal; held-out inputs use different dimensions, circle sections and principal planes. This extends the oracle, not the format writer or production adapter.

Run the same owner-controlled command documented in [curve source authoring](SolidworksCurveSourceAuthoring.md), replacing the specification with `EndConditionSpecs.json` and choosing a new external output directory. Stage the committed author, specification, `Swapp.py` and `OracleIdentity.py` and record the exact source revision. `--case NAME` remains a diagnostic subset that cannot create a family lock. Only a complete sixteen-case run between healthy leading and trailing controls can produce the separate end-condition lock schema. Every worker still requires a fresh owned process, pinned 2026 executable, versioned COM, restored preferences, strict error/warning checks and unchanged input hashes.

Every end-condition case records the complete feature-creation arguments and reads back both termination types, both depths, reversal, the two-direction flag, start type and draft flags. Mid-plane target length is the full requested depth; its independent axial interval is `[-d/2,d/2]`. A two-direction interval is `[-d2,d1]`; reversal maps any interval `[a,b]` to `[-b,-a]`. Volume is section area times interval length, surface area is twice section area plus perimeter times interval length, and the center of mass uses the interval midpoint along the actual sketch normal. Driving edits can target either depth. Native definitions and analytic targets must both agree; a normalized or rejected API request remains a failed observation.

The generator also exports Parasolid text and STEP siblings for these source cases, verifies each export status and verifies that exporting did not alter the native file. It records sibling paths and hashes. Native held-out payloads and their siblings remain sealed during rule derivation and writer implementation. Saved native values and siblings never supply writer output.

API vocabulary is documented in the official [feature-creation reference](https://help.solidworks.com/2024/english/api/sldworksapi/solidworks.interop.sldworks~solidworks.interop.sldworks.ifeaturemanager~featureextrusion3.html), [2026 end-condition enum](https://help.solidworks.com/2026/english/api/swconst/SolidWorks.Interop.swconst~SolidWorks.Interop.swconst.swEndConditions_e.html), [2026 depth read-back](https://help.solidworks.com/2026/English/api/sldworksapi/SOLIDWORKS.Interop.sldworks~SOLIDWORKS.Interop.sldworks.IExtrudeFeatureData2~GetDepth.html) and [2026 two-direction property](https://help.solidworks.com/2026/English/api/sldworksapi/SOLIDWORKS.Interop.sldworks~SOLIDWORKS.Interop.sldworks.IExtrudeFeatureData2~BothDirections.html). The older method reference identifies the argument contract only; actual 2026 authoring and read-back remain necessary. Verification at introduction is source and AST inspection only. No local tests or archive schemas were executed; new native source locks and remote CI are pending. This source corpus adds zero generated writer outputs and establishes no feature-family or production acceptance.
