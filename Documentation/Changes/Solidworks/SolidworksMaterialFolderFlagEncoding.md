# Encode fresh material-folder flags

The research `system_folder` factory now uses the native current-store encoding for a fresh empty material folder.
It writes `flags380=0x80000000` from two constructor-false runtime flags.
The previous zero word used the loader's supported legacy-false encoding.

The [construction record](../../../re/solidworks/records/MaterialFolderConstruction2026.md)
records the concrete receiver, constructor, serializer, field owners and function fingerprints.
It also records the independently computed Boolean combinations.
The [gotcha](../../Gotchas/Conversion/Solidworks/Model/RuntimeMaterialFlagsNeedTaggedEncoding.md)
explains the distinction between runtime flags and the archive word.

## Behavior and use

The [shared factory](../../../re/tooling/sw2026/builders/Model.py) applies the correction automatically.
Callers need no new option.
The [shared serializer](../../../re/tooling/sw2026/serial/defs/ResolvedFolders.py) retains its field order and version gates.
The factory keeps the material string empty and preserves the caller's incoming node name.
This change does not add material assignment or general override authoring.

This is a flag-encoding correction.
It does not change captions or repair the material-folder name change after saving.
The [name-change evidence](../../Gotchas/Conversion/Solidworks/Model/MaterialFolderNameChangesOnSave.md)
remains separate.
The native title-setting operation and resource vocabulary are recorded, but the exact save/reopen caller remains untraced.
The meaning of the second runtime flag remains unresolved.

## Verification and limits

Two static passes independently verified the target module hash, concrete serializer dispatch, function-span hash and packing instructions.
The [older polygon measurements](../../../re/solidworks/measurements/2026/PolygonCurrent/README.md)
apply to the historical generated bytes with wire zero.
They do not establish native acceptance for the changed bytes.

The later [controlled recursive-tree measurements](../../../re/solidworks/measurements/2026/TreeNamesInspection01.json) pass on four generated end-condition outputs using the current word. [Independent remote saved-file decoding](../../../re/solidworks/measurements/2026/TreeNamesReaderF947.json) passes 72 complete archive comparisons and observes the empty material string/current word in all eight derivatives. The first save preserves the authored name; native reopening normalizes its live title before the next save. This corroborates the bounded encoding while leaving full naming/presentation acceptance and the higher-level native caller unresolved.
No local test or archive-parser verification ran.
The new word comes from the native store rule, without saved rows or control-file reads.
The production adapter remains read-only.
The correction introduces no production donor data or CAD-runtime dependency.
