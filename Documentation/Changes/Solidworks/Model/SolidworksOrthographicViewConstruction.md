# Generate separate orthographic view records from semantic input

The shared `src/convert/adapters/solidworks/Archive/Views/` model now validates a semantic rigid rotation, native translation triple and positive scale, then constructs separate orientation and pan/zoom field records. Exact identity omits the optional rotation matrix; other rotations emit their nine supplied coefficients in row order. Orientation has zero translation and unit scale; pan/zoom has no matrix and carries the requested translation/scale. Both records have zero orthographic flags. Boolean/nonfinite values, nonrigid or reflected matrices, mutable coordinate containers and nonpositive scale fail before stream generation.

The research-only `builders/Camera.py` composes this model with the existing part factory and complete definition constructor/serializer. It computes standard orientations from the already documented 2026 quaternion rules and accepts an explicit `presentation.initial_view` mapping containing `named_view`, `translation` and `scale2`. It reconstructs the complete typed definition from neutral data and serializes it; it does not read or patch a saved stream. Existing body/features and all other streams use the same generative model. Existing frozen factory files remain unchanged.

The [field correlation](../Inspection/Presentation/SolidworksOrthographicViewFieldCorrelation.md) supplies the separate-owner rule and exact native evidence. The [two independent native inputs](../Inspection/Presentation/SolidworksUnseenViewSourceLock.md) were hash-locked before this code. Their CAD payloads and detailed API observations remain sealed until the complete camera writer is frozen. These constructors are not production conversion acceptance; the public adapter remains read-only, and arbitrary orientation input, perspective and actual visible viewport parity remain unqualified.

The new `CameraProcess.py` integration process installs the existing audit guard before importing the writer, rejects runtime file/process access during construction, generates a complete container, reloads every critical stream with the proven shared grammar and verifies its linked graph. Discovery requests compare identity and isometric orientation while keeping body input fixed: the optional nine-double matrix must change only definition length by 72 bytes. Negative requests reject Boolean/zero scale, nonfinite translation, unsupported view index and perspective before returning any file. The tests exercise the complete subprocess/container boundary, rather than isolated view helpers.

Introduction verification is source/AST inspection and Black formatting only. Remote process-boundary generation, audit guards, input-dependent stream sizes, full archive comparisons and unseen native acceptance remain pending. No local test, archive parser or writer verification ran. The two sealed native inputs are not part of this discovery integration run; their predictions follow the complete writer freeze.
