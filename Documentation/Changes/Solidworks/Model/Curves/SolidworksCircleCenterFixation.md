# Explicit circle-center fixed-point relation

Research `circle_dimension` requests now accept optional Boolean `fix_center`. When true, the shared model constructs one native logical fixed-point relation targeting the existing ordinary type-zero circle center before adding its radius/diameter dimension. Absent/false preserves the earlier free-center route. It does not turn the center into an origin point, alter topology role counts or copy a training status.

The [construction ledger](../../../../../re/solidworks/records/CircleCenterFixation2026.md) and native metadata bind all new fields, append ownership, accepted-reference counts, cached admission and concrete fixed-node solver dispatch. A shared logical-point constructor also serves the existing separate origin profile, while its own explicit type-one/origin flags remain there. No production writer, body-producing feature or held-out acceptance is enabled.

Two new guarded process cases request fixed centers with independently authored radius/diameter geometry. The native inspector additionally requires public fully constrained status three and exactly one nonsuppressed fixed relation whose entity binding is the actual circle center, with no dangling, overdefining or broken relations. It retains driving edits, unchanged center/plane, save and edited fresh reopen. Installed 2026 type-library metadata binds the public status method/enum separately from native wire fields.
