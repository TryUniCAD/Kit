# Fresh single-circle sketch synthesis

The research part composer now accepts an explicit `profile_kind="circle"`, `feature_kind="sketch"`, local `center_m` pair and positive `radius_m`. It constructs an ordinary profile containing one native arc whose two endpoints share one marker point. This is the first circle sketch synthesis rung. It adds no production adapter writing capability, radial driving dimension or circle extrusion.

The existing document fields still supply names, principal plane, units, provenance, style inputs and target version. Circle sketch requests omit `vertices_m` and `depth_m`. Polygon requests retain their existing default profile/feature kinds. Unsupported kinds, nonfinite or nonpositive radii, unrepresentable marker positions and circle-extrusion requests fail explicitly.

`builders/Circle.py` extends the shared sketch model, `Part.py` composer, typed archive serializer and container builder. The local positive-X marker is computed from the authored center and radius. Node identity supplies the full-circle predicate. Endpoint/center indices, compact selectors, point-use counts, deduplicated adjacency, creation IDs, permanent markers, array counts and pre-solve stamps come from the modeled construction sequence. No file, saved stream, captured row or recorded field program supplies output values.

The symbolic graph follows the documented native constructor and permanence operations. Its ordinary entity colors/statuses, sketch current/saved states and empty runtime-derived caches begin at constructor states. The [first controlled inspection](../../../../../re/solidworks/measurements/2026/CircleSketchInspection01.json) established healthy native load/rebuild/save/fresh-reopen behavior for two free-circle sketches on different principal planes. It does not establish the final stored status words, universal cache neutrality, constrained-circle solve behavior or solid contour regeneration. No completed solve or callback preservation is inferred from byte identity.
