# MFC probe process-architecture admission

The first committed MFC runtime probe rejected its owned Python process before loading MFC. The original guard required the `IsWow64Process2` process-machine output to equal AMD64. The actual run returned `0` for that field while reporting a native ARM64 host, eight-byte pointers and an AMD64 Python executable. The changed [probe](../../../../re/tooling/sw2026/InspectMfcRuntime.py) queries the process's actual architecture and its own mapped executable before admitting the selected analysis process.

`GetProcessInformation` now requests `ProcessMachineTypeInfo`, enumerator value `9`, with the eight-byte `PROCESS_MACHINE_INFORMATION` structure: two 16-bit fields followed by the 32-bit machine-attributes value. Its documented `ProcessMachine` field identifies the associated process architecture; the probe requires AMD64. Reserved data is not interpreted, and machine attributes remain a raw observation rather than instruction-set proof. These contracts are documented by Microsoft for [the query](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocessinformation), [the information class](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/ne-processthreadsapi-process_information_class) and [the result structure](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/ns-processthreadsapi-process_machine_information).

The same current-process pseudo-handle supplies the main-image module information. Its mapped path must identify the inspected Python executable. Bounded current-process reads validate a PE32+ AMD64 header and matching OS/header image bounds, and record a header length/hash. The raw executable must independently report AMD64. This creates no extra binary capture and reads no other process. The handle obtained through [`GetModuleHandleW(NULL)`](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-getmodulehandlew) acquires no new reference and is never passed to `FreeLibrary`.

`IsWow64Process2` remains required for the observed native ARM64 identity and continues to report its original process-machine value. A zero classifier is not rewritten to either AMD64 or ARM64. It is admissible only when the actual-process query, raw executable and mapped executable independently agree on AMD64, with eight-byte pointers and a native ARM64 host. A nonzero classifier other than AMD64 conflicts with that selection and fails. API failure, unsupported structure/header framing or any disagreement stops before MFC load; there is no fallback to a Python architecture string or raw file alone.

`process_architecture.machine_type_information` records the new query, and `python_mapped_image` records the main-image identity. `process_architecture_verified` becomes true only after the entire process admission succeeds. The MFC mapping/export checks, exact runtime/helper/discovery hashes, fixed capture limits, fresh external output, owned-reference cleanup and prohibition on archive-method invocation retain their prior behavior. An admitted process still does not prove an unambiguous mapped MFC view, code instruction set or count grammar.

The command-line interface is unchanged; see the [runtime-view entry](SolidworksMfcRuntimeViewInspection.md) for staging and invocation. The oracle owner must commit and freeze this changed source, use a fresh Python process and unused output path, and preserve failure `01` before a causal rerun. The [gotcha](../../../Gotchas/Conversion/Solidworks/Inspection/WowClassificationDoesNotIdentifyProcessMachine.md) records the immutable first failure and the primary API distinction. No result from the new query or mapped-main-image path has yet been measured.

Local verification was AST parsing and static API/source/link inspection only. No tool import, probe, schema, codec, test, CAD/held-out payload read, VM command, COM call, service or licensing action ran in the implementation worker. `instruction_set_proven`, `native_implementation_bound` and `acceptance` remain false. The string-map count implementation and separate radial callback boundary remain unresolved.
