# SOLIDWORKS material and display archive owners

The research archive registry now has independent shared owners for eight material, model-data, display, line-visualization and line-width method grammars. These were actually used as provisional schemas by the 26 discovery/control curve inputs. Their wire rules now trace to complete functions in the pinned SOLIDWORKS 2026 SP05.2 binaries, rather than fixture values or a blanket change to provisional status.

The new owner module is [MaterialDisplay.py](../../../../re/tooling/sw2026/serial/defs/MaterialDisplay.py). It defines `PWMaterialManager_c.restore`, `uoModelData_c.restore`, `uoDSPBRProperties_c.restore`, `moDisplayItem_c.Serialize`, `moDisplayObject_c.FUN_4ba4d3c0`, `moLineViz_c.Serialize.0`, `utLineWidth_c.Serialize.3.0` and `utLineWidth_c.Serialize0`. Existing field keys are preserved. Sorted registry loading replaces the earlier tentative declarations; later provisional helpers cannot override these owners. Existing schema, round-trip and field-inventory implementations are unchanged.

The [independent format record](../../../../re/solidworks/records/MaterialDisplayArchive2026.md) gives field order, widths, version gates, pointer-presence framing, optional references, native list dispatch and full function/module hashes. It explains the private PBR helper's concrete receiver, all 70 current PBR fields, nonempty display-list grammar, signed versus unsigned loops and native point/vector count bounds. It also distinguishes wire retention from native material filtering, appearance-path rewriting, flag repair, cached widths and canonical saves.

The two display owners explicitly require effective version `19000` and reject data-location condition `1` and alternate linked-object condition `0x10000000`. A present watermark record still rejects explicitly. Other versions and nested owners do not gain unverified coverage. Material/model-data and line helpers retain their independently verified gates; the old model-data light path remains unsupported. Native line-width save and read formats differ for older versions, so source reconstruction does not claim canonical native saving for those versions.

Remote usage follows the existing [schema guide](../../../../re/tooling/sw2026/serial/README.md) and 26-file process checks. Require complete, byte-identical primary and linked reports with zero tails and empty actually used provisional/missing inventories in load, store and linked dependency phases. Retain failures and process receipts. Neither an installed authoritative declaration nor an empty registry inventory establishes that the exercised graph is closed; see [the usage gotcha](../../../Gotchas/Conversion/Solidworks/Archive/ProvisionalSchemasDoNotProveClosure.md). The [wire-state gotcha](../../../Gotchas/Conversion/Solidworks/ArchiveWireValues.md) and [display-getter ownership gotcha](../../../Gotchas/Conversion/Solidworks/Profile/DisplayGetterAliasesDoNotDetermineFieldOwnership.md) explain relevant interpretation traps.

Verification for this change is static only: AST parsing, exact owner-name and field-key review, binary import/vtable binding, independent hashes of 22 complete functions and four complete leaves, relative links and formatting. No local codec, registry, product or test execution occurred. No native input or held-out payload was inspected. The retained prechange reports and hashes in the format record are historical scope evidence, not postchange CI results. Fresh remote admission remains pending, and the other used provisional owners remain independently gated.

This is discovery/control source-parser research. It supplies no fresh feature writer, saved-data fallback, constructor defaults or native rebuild/edit acceptance. The [CAD success criteria](../../../Reference/Operations/CadSuccessCriteria.md) remain mandatory: “The first is success under every criterion on this page.” and “The second is the end of the available context.” The generative-curve goal remains unfinished and production SOLIDWORKS support remains read-only.
