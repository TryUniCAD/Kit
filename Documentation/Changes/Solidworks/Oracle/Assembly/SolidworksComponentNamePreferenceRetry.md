# Owned component-name preference retry

PR #121 adds a narrowly authorized temporary name-update preference around the independent native custom-name author/save control. It captures the actual original value before mutation, writes durable armed/applied/restored receipts, restores and verifies in `finally`, then performs the primary fresh reopen under the original setting with unchanged source geometry, names and acceptance checks.

Use [the record](../../../../../re/solidworks/records/CustomComponentNamePreferenceRetry2026.md), [freezer](../../../../../re/tooling/sw2026/FreezeCustomComponentNameRetry01.py), [observer/recovery entrypoint](../../../../../re/tooling/sw2026/InspectCustomComponentNameRetry01.py), [lease helper](../../../../../re/tooling/sw2026/ComponentNamePreferenceLease.py) and [host receipt](../../../../../re/solidworks/measurements/2026/CustomComponentNamePreferenceRetryHost01.json). The [setter collector](../../../../../re/tooling/sw2026/CaptureComponentNameSetterApi01.py) binds the actual integer/Boolean-to-void signature; native getter read-back establishes setting state.

The earlier true-preference failure and its healthy controls remain unchanged. The 48-file successor passes host verification, unchanged-prediction, syntax and undefined-name checks. New native authoring, restoration, fresh reopen and recovery remain unmeasured. It adds no writer or database output, production registration or held-out claim.
