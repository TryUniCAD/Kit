# SOLIDWORKS same-file read-only component-name probe

The disclosed native custom-name source preserved both labels on disk but normalized them on reopen under the restored true preference. The new research protocol tests that exact unchanged pair under a temporary false setting, with the same names, IDs, geometry and full feature-tree predictions.

The freezer binds the previous terminal result and original source routes, snapshots and independent expectation files. The observer reuses the two pristine controls, requires actual original true, records matched names before strict checks, opens the source read-only and performs no document setter, dimension edit or save. A distinct durable read-only lease restores the actual original value in `finally` and verifies it.

The frozen recipe contains host/guest verification, three serial native phases, summary and a separate idle-only recovery command. Recovery requires exact captured/armed original-true receipts, verifies its own tools and never depends on reopening the source files. Its tool-only host verifier opens no CAD payloads and performs no setting change.

Host verification covers 63 frozen files, unchanged original predictions and
both 25-row trees. All three native phases passed with 84 numeric checks.
Under the temporary false setting, the same two occurrence IDs kept their
custom names through fresh open and rebuild. The assembly and child retained
both expected trees. The source files stayed byte-identical and the original
true setting was restored and read back. No document setters or saves ran.
Generated or public qualification remains open.
