# Through-all source system-member construction

PR #121 adds a private internal construction component for actual cabinet note pairs and explicit ambient/directional light scenes. The source mapper reaches actual D01–D03 children by typed owner identity and preserves their semantic inputs. The constructor allocates fresh nodes, counts and references through the actual shared model graph. The revision validator permits only verified one-level member ownership and leaves its existing direct-owner behavior intact.

Use `ReadThruMembers` with the complete source and actual linked graphs, then `AttachMembers` with the already constructed part system and shared allocator. This component requires one actual active configuration and empty target member lists. It does not read session preferences, invent a default four-light scene, replace existing members or enable complete-source/public writing.

Seventy-four fresh host processes pass, including 44 SDK-boundary rejections, variable two/five-light scenes, source six-child ownership, 30 fragment round trips, actual 28-log Header joins, independent ambient compatibility and unchanged default containers/public reads. No native lifecycle or original held-out qualification ran. All 19 SDK paths pass static checks and the donor scan.

The allocator checks capacity before it creates any member. A five-process
follow-up preserves all three disclosed builds exactly, refuses capacity
exhaustion without modifying allocation or owner lists and rejects a nested
note whose revision log uses an invented direct model owner. See the
[boundary receipt](../../../../../../re/solidworks/measurements/2026/ThroughAllMemberAdmissionBoundary01.json).
