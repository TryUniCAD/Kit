# Native compatibility scheduling

The workflow-quality policy job now runs repository contract checks separately from native-file compatibility. Four parallel native shards retain the complete SOLIDWORKS, Parasolid and rationale test paths, Python 3.11 and frozen dependencies. The existing shard planner partitions the collected roster with deterministic fallback weights; a shared report verifier requires every collected case exactly once. Per-case outcomes and twenty slowest durations are retained as artifacts. Shards use twelve-minute limits at the user’s explicit request; the policy job keeps its ten-minute limit and the report verifier uses five minutes. No assertion, test path or acceptance gate is removed.

Merge candidate `06b002441448d2e961629215cdc09768ea8b1530` exceeded the combined job's ten-minute limit. Its contract checks passed 406 cases in 29.21 seconds; native checks passed 498 cases with 159 recorded skips in 541.39 seconds. Setup and finalization exhausted the remaining budget. GitHub's annotation explicitly reported the execution deadline.

All four shards and their exact-once report are mandatory merge-candidate checks in the phase registry consumed by the CI allowlist. Queue aggregation process coverage includes success, failure, cancellation, timeout and skipped outcomes for each shard and the report gate. PR validation defers the groups to merge-candidate acceptance. Current candidate acceptance remains required; the failed candidate is retained as evidence.
