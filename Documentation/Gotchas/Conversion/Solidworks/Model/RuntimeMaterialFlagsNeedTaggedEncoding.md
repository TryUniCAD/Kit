# Material runtime flags need tagged archive encoding

## Expectation

A fresh material folder has two false runtime flags.
Writing their raw zero value appears to reproduce the current archive representation.

## Observed behavior

The 2026 material-folder constructor clears runtime fields `+0x380` and `+0x384` separately.
Its [current serializer](../../../../../re/tooling/sw2026/serial/defs/ResolvedFolders.py) packs both predicates into one unsigned archive word.
It also sets bit 31 to distinguish that encoding from the older single-Boolean representation.

The rule is:

`wire_flags = 0x80000000 | int(runtime_380 != 0) | (int(runtime_384 != 0) << 1)`

When bit 31 is clear, the loader interprets any nonzero word as a true first flag.
It clears the second runtime flag.
When bit 31 is set, the loader restores the first two bits independently.
Thus an untagged `0x2` would decode as `(True, False)`, not `(False, True)`.
This example follows from the loader instructions, not a captured row.

The previous fresh factory word `0` follows the explicit legacy-false branch.
It is not evidence of a rejected file.
The native current-store word for the two false constructor states is `0x80000000`.

## Workaround

Compute the archive word from both runtime predicates and the format marker.
Keep the runtime fields separate from the wire field `flags380`.
The [shared research factory](../../../../../re/tooling/sw2026/builders/Model.py) now supplies `0x80000000` for its fresh empty material folder.
Keep material assignment and other override states outside this bounded factory contract.
The second runtime flag's semantic name remains unresolved.

This correction does not change the material string or incoming feature name.
The [name-change gotcha](MaterialFolderNameChangesOnSave.md) records a separate measured save/reopen behavior.
No cause for that name change is inferred from the encoding difference.

## Evidence and limits

The [construction record](../../../../../re/solidworks/records/MaterialFolderConstruction2026.md)
binds the constructor, actual serializer dispatch and packing operations to the pinned 2026 module.
The [change entry](../../../../Changes/Solidworks/SolidworksMaterialFolderFlagEncoding.md)
describes the current factory behavior.

The historical polygon results cover the old generated bytes.
Remote CI and controlled native measurements for the changed bytes remain pending.
Native generated-output acceptance is withheld.
No local tests or new oracle measurements support this static correction.
The production SOLIDWORKS adapter remains read-only.
