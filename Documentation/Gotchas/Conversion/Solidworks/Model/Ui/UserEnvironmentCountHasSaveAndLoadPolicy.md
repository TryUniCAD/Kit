# A user-environment count is not a presence flag

`nenv` is the declared unsigned16 count of typed environment objects, not a Boolean, fixed one, or guaranteed count of live restored windows.

Before counting, native save can create/update the current-user environment from the real frame, username and splitter state. A null buffer writes zero; otherwise count comes from actual dynamic-array metadata. Native load consumes the declared loop and can filter null or already-present user entries before live insertion. Additional compatibility/selection policy remains separate.

The part has both primary and secondary splitter bodies; the drawing context omits the primary one. Reusing the drawing omission or the fresh zero-row constructor does not preserve an existing part's actual window state.

The typed count audit verifies count, actual rows and concrete class/schema. It adds no window factory and grants no full-source admission. Both disclosed sources have a saved row; the incomplete fresh graph still has none, so their two environment frontier markers remain open. Do not silently erase that discrepancy or claim byte/pose parity as full source preservation.
