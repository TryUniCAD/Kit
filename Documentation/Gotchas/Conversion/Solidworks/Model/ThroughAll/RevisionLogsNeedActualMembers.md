# Through-all revision logs require actual system members

## Expectation

The source Header can be preserved by adding the cut class to the ordinary revision-owner whitelist and copying every source log's numeric target.

## Actual behavior

Each disclosed D01–D03 source has 28 actual logs in each Header. Six belong to the cabinet's two persisted note members and the environment's ambient plus three directional lights. The fresh through-all system factory does not construct those target features. Its runtime-only default state is not a set of persisted identities that can own source revisions.

A source numeric ID can collide with a different freshly allocated node. Matching a caption is also insufficient. Extending the allowed cut class does not construct the missing owners or preserve their containment, state or chronology.

## Workaround

Retain the complete source envelope and full-source refusal. Construct the actual typed system members from independently established semantic inputs, allocate their real target IDs, then bind each revision intention by actual source-to-target ownership before Header emission. Do not forward source ID words or synthesize empty substitute logs.
