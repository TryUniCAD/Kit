# A keyword join may create a new stock

## Expectation

The keyword-derived operation mode `join` and its dependency on the preceding solid imply that the second boss merged with the first.

## Actual behavior

In the disclosed two-stock save, the second boss is a schema-one `moICE_c` with new-solid field `f810 == 0`. Its actual history list owns its own profile. It produces atom 102 and survives untouched after the selected through-all cut. The keyword-derived operation calls it `join` and includes feature 32, the first boss, as a supposed input.

## Workaround

Use the actual typed operation, profile, end and atom owners. Project the second boss as an independent creation with its own input and D1. Build the cut's historical selection from its consumed atom, and link the untouched and cut-result atoms to their own saved B-rep bodies. The [selected saved profile and process evidence](../../../../../../re/solidworks/records/ThroughAllMultiStockDocument2026.md) record both routes.
