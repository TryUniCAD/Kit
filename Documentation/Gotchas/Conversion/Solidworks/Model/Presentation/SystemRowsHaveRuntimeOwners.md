# Saved system rows need not be new modeling steps

## Expectation

A native save preserves the number and classification of public modeling rows.
Every keyword entry describes a new feature root.

## Actual behavior

The disclosed ordinary part has 19 typed roots before and after save, while
the old public timelines contain 19 and 27 rows. Native COM reports the same
25 presentation rows in both states. The saved extras include note-folder
partners inside the annotation cabinet, lights inside the environment and two
direct configuration managers outside the measured feature UI. The origin's
keyword type also changes to `Sketch` despite its unchanged typed class.

An empty fresh environment does not encode four fixed lights. The native
creation routine obtains its default-light collection from session settings.
Invented native IDs or a generic negative-ID filter would conceal this
distinction and could remove authored state.

## Workaround

Use actual typed owners, classes and containment. Keep persisted system state
separately from modeling history. Give implicit defaults owner-role identities
with null native IDs and state, and state the selected session profile.
Preserve unqualified/custom rows and populated managers. Derive admitted root
types from their actual classes while retaining the keyword label.

The [record](../../../../../../re/solidworks/records/SystemTreeProjection2026.md)
and [paired receipt](../../../../../../re/solidworks/measurements/2026/SdkSystemTreeProjection01.json)
define this bounded profile. They do not qualify arbitrary settings, languages,
captions or runtime status flags.
