# Category maps use sampled UTF-16 buckets and own separate fonts

A category map cannot be reconstructed by lexical sorting, Python hashing, hashing every Unicode character, or sharing one object for equal font names.

The exact native constructor uses seventeen buckets. Effective ARM64X/ARM64EC lookup samples UTF-16 code units at stride `floor(unit_count/10)+1`. An unsigned multiply-then-xor hash precedes case-sensitive wide-string equality. New keys prepend to chains; store walks increasing buckets and then each chain. Equal font names still receive distinct category-owned copies.

The raw ARM64X export table is not the reached AMD64-compatible view. Resolve the declared hybrid relocation view and actual UI imports before assigning a target. Do not use a guessed architecture heading or order.

The typed component derives the walk from explicit insertions and creates one font per category. Source projection verifies a compatible inverse insertion plan without claiming original call history. Unknown ordering or aliasing is refused.
