# Observation identity labels need retained owners

An object's Python identity is unique while that object is alive. An integer identity table does not keep the object alive.

The private origin intake labeled nodes across separately decoded graphs. Its temporary drawing `Header2` graph was released after observation. Later history nodes could receive the same Python identities. The report then assigned one observation label to distinct native classes and independent map indices.

The normalization guard correctly refused those aliases. Eleven conflicts occur between drawing-header observations and the later drawing-history observation. None occurs within a single graph snapshot. These conflicts do not prove a CAD graph defect.

Retain actual node references for each complete observation case. Verify object identity before assigning a label. Release the references only when that case ends. Preserve the old report and create a fresh observation. Do not merge records or rename colliding labels to make the old report pass.
