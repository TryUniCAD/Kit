# Support aliases retain preallocation marks

The ordinary drawing support factory creates a component-plane wrapper before allocating the plane's persistent feature ID. `MakeSheetRef` retains `ff0=(-1, native unset time)` and installs the actual plane object at `ff8`. The same plane later receives its ID and is published in the view. A numeric `ff0.f00` lookup is therefore not the saved support-ownership rule for this path.

The first private origin-source normalizer failed to find either generated view support because it searched the view's allocated plane IDs for -1. The wrapper's physical `ff8` alias already identifies the correct concrete plane. The source and generated graphs preserve this distinction.

Use the actual alias and require the plane and profile to belong to the selected view. Require that plane to appear exactly once in the actual view child list and that the local component owner is the actual drawing model. Keep the retained preallocation mark as separate source state. Do not change it to the later plane ID or choose a plane by its caption.

The [linked Definition record](../../../../../../re/solidworks/records/DrawingLinkedDefinition2026.md) and [scaled support record](../../../../../../re/solidworks/records/DrawingScaledSupports2026.md) describe these actual plane aliases and owners. This observer correction changes no generated bytes or writer admission.
