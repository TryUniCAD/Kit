# Dimension text can acquire a native depth offset

The disclosed rectangle author requests `AddDimension2(x,y,0.0)`. The saved height display in each of four disclosed children contains `moDisplayDistanceDim_c.f6a0.f38.z = 0.0001 m`, while the display transform is identity. Width text retains zero Z. The nonzero stored height coordinate is therefore observed post-author state; it is not evidence that the caller requested a nonzero depth.

The frozen SDK rectangle-dimension input accepts two planar coordinates, and its display constructor writes text Z as zero. Do not flatten the observed saved point, infer a universal native layering constant, or claim that an API call with zero Z proves a saved zero Z. The exact native mutation and whether this offset is semantically disposable remain unproved in this tranche.

The private portable observer retains all three coordinates and the actual display owner. It emits no runnable constructor request for an unrepresentable nonzero text depth. This is separate from source style, history, manager-name and body-name boundaries, which also remain explicit.

The [rectangle constructor ledger](../../../../../../re/solidworks/records/SdkRectangleDimensions2026.md) defines the existing planar scope. This observation does not change that constructor or its prior native qualification, and does not qualify original drawing conversion.
