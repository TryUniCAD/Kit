# Automatic circle names are not wire constants

An ordinary new circle dimension is normally named `D1`. The pinned native naming path obtains that result by formatting the prefix `D` and first available integer candidate. The parameter itself owns a separate name object, whose serializer stores caller text.

The SDK's plain-circle preparation currently requires `D1`. That guard is narrower than the inspected name-object grammar. The shared length-parameter constructor already accepts an explicit leaf name, but the circle wrapper omits it and the circle depth/keyword path separately hardcodes `D1`.

Do not delete original source names to pass this guard, or treat a changed keyword string as a renamed live dimension. Bind the real parameter, display and keyword to the same admitted name, retaining the source ID and actual owner. The native setter can also set secondary node mask `f2c` mask `0x1` when the name equals an unclassified resource-dependent token. A text-only mutation is therefore not a general rename implementation. Keep custom-name lifecycle closed until native edit/save/reopen checks establish syntax and collision behavior.
