# A fresh fillet definition can report a null edge

On SOLIDWORKS 2026 SP05.2, the disclosed axial stock's only mark-1 selection compared equal to the intended `IEdge`. After the fresh `ISimpleFilletFeatureData2.Edges` setter returned, its getter returned one null element and `GetEdgeCount` returned 1. Passing the null pointer to `ISldWorks.IsSame` raised COM type mismatch before the fillet was created. Both stock-face identity checks and the actual marked-edge comparison had succeeded in the same process. [Exact failed phase and bracket evidence](../../../../../../re/solidworks/measurements/2026/EdgeFilletSourceAttempt01.json)

For this ordinary constant-radius creation route, verify the live mark-1 edge through the selection manager and pass that selection to `CreateFeature`. For saved definition readback, acquire rollback selection access and require the actual nonnull edge to match the stock body, endpoints and native identity. Release selection access before measuring the active solid. Nullness on the fresh property does not establish a general COM proxy failure or a saved-format rule.
