# An assembly open can return unresolved references

A SOLIDWORKS 2026 `OpenDoc6` call can return a usable parent document pointer and `swFileNotFoundError` (`0x2`) when a referenced file cannot be located. In the disclosed generated distance trial, the parent exposed its stored occurrence transforms, yet the first component's `GetModelDoc2` returned null before and after a successful `ForceRebuild3` call. [OpenDoc6](https://help.solidworks.com/2026/English/api/sldworksapi/SOLIDWORKS.Interop.sldworks~SOLIDWORKS.Interop.sldworks.ISldWorks~OpenDoc6.html) · [Load error flags](https://help.solidworks.com/2026/English/api/swconst/SolidWorks.Interop.swconst~SolidWorks.Interop.swconst.swFileLoadError_e.html) · [Distance setup observation](../../../../../re/solidworks/records/GeneratedDistanceMateOpenSetup2026.md)

For a controlled assembly load, stage the parent and child at the exact paths encoded by the request and bind their hashes. Record the returned pointer, load flags and exact parent path separately. Query each occurrence's path and suppression state, then require its loaded child document to match the intended file before checking its geometry or mate solve. The 2026 API does not switch the working directory to the opened parent directory.
