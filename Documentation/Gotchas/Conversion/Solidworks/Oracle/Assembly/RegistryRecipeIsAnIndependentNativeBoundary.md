# A public recipe needs its own native qualification

An internal constructor can pass both pre-writer-locked native cases while the normal registry still emits different complete files. In the disclosed G01 projection, the public path changes 76 typed input fields across the child/root recipes, annotation text and one unit-conversion double. It uses existing defaults rather than the internal experiment's presentation and save inputs.

Those changes include the visible child environment name, material-density preference and save-as-part tolerance as well as style, provenance, timestamps and tessellation. Source field ownership explains the differences; it does not establish their complete native behavior. Forcing old research values into the public default recipe would also alter earlier supported outputs.

Keep established defaults intact, preserve every field classification and measure the exact actual registry output with independently predicted geometry and full native trees. Leave qualification flags false until that complete output passes. If the common strict policy refuses those flags, use only an explicitly scoped research permission and verify zero actual carrier content rather than changing the common policy or claiming usability.
