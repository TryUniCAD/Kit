# Component names require their actual API and archive owners

## Expectation

A native `Name2` label can replace the neutral occurrence name, or a binary string matching `Name2` identifies the component getter.

## Actual behavior

The disclosed neutral and generated archive explicitly retain occurrence names different from the child file stem. The native component label differs, while the actual loaded feature name is not yet measured. The first strict failure is name membership. A matching binary property label also occurs next to routing-specific properties and has no complete component-interface binding.

## Workaround

Read actual `IFeature.Name/GetID` alongside the matched specific component's `Name2/GetID/path`, before the unchanged strict gate and in both controls. Keep node names, dependency filenames and API labels separate until their owner and refresh path are proved. Do not fit the expected name, invent a runtime override as a wire field, or change global naming preferences.
