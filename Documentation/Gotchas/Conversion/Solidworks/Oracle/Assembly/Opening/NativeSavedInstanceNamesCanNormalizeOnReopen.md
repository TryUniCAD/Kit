# Native-saved instance names can normalize on reopen

A successful actual `Name2` setter and native save do not prove that a custom instance label survives the next application process. In the disclosed exact 2026 source control, both intended custom labels were retained in the saved typed reference graph and matched `IFeature.Name`, but fresh read-only open under the restored true update-name preference returned child-definition-based labels through both interfaces. The native IDs and child file identity were unchanged.

Keep persisted names, loaded names and actual settings as separate evidence. The ordinary native synchronization can call reference `changeName` with the child definition's name. The reference runtime override at `+0x540` is not a new current wire scalar; the external synchronization flag is one serialized byte and the native store clears its bit `0x10`.

Do not fit expected labels, rename the shared child definition or insert a runtime-offset scalar into the archive. Use the unchanged file in a separately bracketed read-only setting discriminator, with durable capture and finally restoration, before attributing a writer defect or claiming a format fix.
