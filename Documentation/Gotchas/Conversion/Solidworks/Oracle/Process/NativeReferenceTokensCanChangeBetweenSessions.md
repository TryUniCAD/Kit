# Native persistent reference bytes can change twice across save and reopen

On exact SOLIDWORKS 2026 SP05.2, two disclosed generated F14a parts preserve all captured boundary references through one Height edit, Save As and fresh open. Each part's 26 refreshed boundary tokens keep the baseline digests across the live edit. Save As changes every boundary digest and adds four bytes per token. The fresh open changes all boundary digests again at the same lengths. The producing extrusion's 20-byte token keeps its digest throughout. [Exact phase evidence](../../../../../../re/solidworks/measurements/2026/F14aLiveReferencePersistence01.json)

Retain the original bytes in the oracle and resolve them through `GetObjectByPersistReference3`. Check the resolver status, actual selected object, producer and geometric role, and compare issued tokens using `IsSamePersistentID`. The two lifecycle records have success status `0` and equality `1` throughout both digest transitions. Token length and digest are transport observations. They supply no file format generation rule.
