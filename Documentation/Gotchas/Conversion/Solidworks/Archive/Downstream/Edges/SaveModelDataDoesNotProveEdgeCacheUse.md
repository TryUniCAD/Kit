# SaveModelData does not prove edge-cache use

An enabled drawing save-model-data option permits native edge-map storage. It does not demonstrate that a generated child's downstream ID map supplied the attached edge.

The exact 2026 public enum is document preference 779 with option0. The model-side getter reads `moDetailDefs_c.f220`; its setter writes that member and passes the old/new values into the UI callback, while the standard-view-palette option780 owns f224 separately. There is no justified universal default in this proof.

The ordinary drawing's detailing preparation can consume the child cache before save event7. The historic aggregate observer was deliberately constrained to stops after event7, so it cannot be reused unchanged to observe those earlier call/return sites. A missing delivered stop is unobserved, not proof of a fallback or a successful cache lookup.

Check the public setter/readback/persistence and the actual non-dangling edge attachment in a control-first lifecycle. Observe cache use separately through a qualified owned-process pre-event7 trace with exact ID/owner/frame evidence, original instruction restoration and confirmed detach. The [source protocol](../../../../../../../re/solidworks/records/DrawingEdgeComQualification2026.md) and [field producer](../../../../../../../re/solidworks/records/DrawingEdgePreferenceProducer2026.json) preserve the distinction. Native edge-annotation qualification remains pending in this delivery.
