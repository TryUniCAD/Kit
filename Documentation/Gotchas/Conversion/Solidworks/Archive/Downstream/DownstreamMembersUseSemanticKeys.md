# Downstream members use semantic keys

A fresh downstream constructor has a null `f40`, so it is tempting to keep that state or replace it with one id representation per geometric face. The populated create path does neither.

The actual batch collector walks selected bodies, faces and then edges, obtains each entity's real id-attribute history, and appends a concrete clone only on the native entity-data comparator's new-key branch. Repeated comparable keys update mappings without another append. Keys can retain an older actual feature, creation time and file/config owner; a new cache does not make all keys refer to the last feature.

Preserve first-encounter order and the real comparator/clone ownership. Keep kernel order, edge-id subtype closure and copied FR/external owners explicit. A face-count formula, pointer-only deduplication, captured list or blanket empty default does not reproduce this mechanism.

The [exact-build evidence](../../../../../../re/solidworks/records/DownstreamIdentityMembership2026.md) pins the complete producers and limits. This is static format knowledge, not acceptance of a generated cache.
