# Header creation does not order every archive clock

The fresh constructor's common creation input and `ModifiedAt >= CreatedAt` rule can look like native file-format requirements.

They are a narrower construction policy. In SOLIDWORKS 2026, `setCreationTime` can update header creation and the self-file identity without updating the first root revision event. Version history constructs its own event stamp. The header's archive-time member has a sentinel-year repair; its serializer has no modification-versus-creation ordering check. The native latest-modification getter instead examines revision-log tail events.

Preserve each actual typed owner when reading. For new output, retain current admission guards until independently chosen split-clock candidates have controlled native evidence. Do not replace an origin's actual creation event with the header or version-history clock, or turn a saved example into a default.
