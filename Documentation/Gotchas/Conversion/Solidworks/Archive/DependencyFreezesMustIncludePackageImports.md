# Dependency freezes must include package imports

## Expectation

A manifest that lists the archive classes, builders, schema directory and process
helpers freezes every project module read by a fresh writer process.

## Actual behavior

The camera process's recorded import audit contains 2,456 project source modules.
Of those, 2,280 were outside the 354-file manifest. Importing the public package
initializers triggers adapter discovery and imports other format modules.
Most recorded paths name `.pyc` files, so checking only paths ending in `.py`
misses this dependency set.

All additional source files are unchanged between camera source authoring,
the pinned writer source and the accepted prediction merge. The accounting gap
does not change the measured generated bytes. It does make the earlier claim
that the explicit 354-file table was complete too strong.

## Workaround

Translate `__pycache__/Name.cpython-311.pyc` audit paths to their source paths.
Include package initializers and discovery imports, with exact source identities.
Preserve historical source separately from current edits, execute it in a fresh
interpreter and require the original measured output hashes. Also compare current
output independently and reject project imports from the editable current tree.

The [historical cohort workflow](../../../../Changes/Solidworks/Inspection/Cohorts/SolidworksFrozenCohortRegression.md)
implements that separation. Its [source inventory](../../../../../re/solidworks/v2026/heldout/FrozenCohortSource.json)
contains Git object IDs, lengths and SHA-256 values only. It contains no saved
CAD payload or recorded field program. New source behavior requires new unseen
inputs; historical reruns remain regressions.
