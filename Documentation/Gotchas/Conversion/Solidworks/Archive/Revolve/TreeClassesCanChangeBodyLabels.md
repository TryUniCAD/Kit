# Tree class normalization can change body labels

The existing body selector consumes native feature discriminator strings. Changing a legacy revolve discriminator into its concrete `Revolution` class can therefore change the projected body label, even when the typed tree and geometry are unchanged. Preserving only the boss discriminator can be worse: normalizing the solid-body folder then lets that generic selector choose the folder as a body.

The first private source-reader draft exposed both effects. The corrected qualified revolve tree preserves every original discriminator while retaining actual class/name/parent ownership in typed metadata and the correct root order. Existing body labels, final-feature links, geometry and payload policy remain exact across cached and cache-free reads. The shared bare-boss and through-all normalization stays unchanged.

The disclosed source COM records report body count and mass properties without body labels. Their typed current-partition name probe also refuses an unmapped kernel class before ownership qualifies. Do not invent a body name from the visible tree. Keep the original projection until an actual body-name owner or a controlled native observation binds the label.
