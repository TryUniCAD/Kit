# Header counts follow configuration activity

The native header's component count is not a visible-feature count. The
configuration constructor's activity-count seed is also not a completed saved
count.

In the 2026 normal assembly configuration path, the reference-walk handler
resets the configuration's activity count at the embedded self reference and
increments it once for each later event with zero completed status. The
configuration controller passes that result through the document context to
the UI document and header. Suppression, graphics, nested paths and special
component modes affect selection or status; shrink-wrap configuration has a
separate source. A similarly named component-count walker is used for
tessellation statistics and does not establish this header rule.

Keep the initial -1 configuration seed, computed activation count, UI cache and
header copy distinct. Derive a neutral-model rule only after closing the
relevant traversal predicates. Do not copy a saved count, fit it to a feature
ladder, or replace it with zero to make an assembly writer proceed.

The [construction record](../../../../../re/solidworks/records/AssemblyConstruction2026.md#header-component-activity-count)
binds every native address to module hashes and lists the remaining constraints.
This is static evidence; held-out generated-assembly acceptance remains
unproven.
