# Derived normal selections need owner proof

The public SOLIDWORKS part reader emits a direction-axis selection for an extrusion's sketch normal. That neutral selection is generated by `DirectionAxis`; its presence alone does not prove a user-authored selection that a fresh constructor must store separately.

The private origin-source normalizer first rejected all eight children with a generic unsupported-domain diagnostic. Each actually had only one extra domain record: the reader-derived `N_Axis` selection. Materials, meshes and B-rep payloads were empty; native boundary and assembly were null. The selection query names the actual boss and profile, its one path names that sketch's native normal, and no feature consumes its ID. The actual typed ordinary blind end has no explicit direction or referenced-direction object.

For this bounded profile, represent that direction with the actual Front support and the ordinary forward blind end. Require the complete owner/query/path match, no authored point or attributes, and no explicit consumer. Retain the original selection row in the reversible source ledger. The constructor remains unchanged and still refuses arbitrary selections.

Do not drop every direction selection or use its display name as proof. Extra selections, a different owner/target, an explicit direction, a selected reference, authored attributes or another supported-plane mode require their own representation or an explicit refusal.
