# Generated principal planes do not use vendor plane numbers

## Expectation

The owner-validated principal sketch reference reader from PR #270 should recognize every principal sketch attachment, including parts generated by Kit's SOLIDWORKS writer.

## Actual behavior

The owner and pose reader only accepts principal plane object IDs 2, 3 and 4, which SOLIDWORKS uses in its own saves.
Kit's generative writer gives principal planes fresh IDs, such as 14 for the Front plane in a generated blind pocket.
The origin pose of those parts fails that check, so the origin owner is unknown.
PR #121's frame-checked plane handle then becomes the only reader that recognizes those attachments.
Applying that handle to every part with an unknown owner breaks the PR #270 contract.
Corrupted owner envelopes and unreadable vendor origins would return a typed plane reference instead of the unqualified stream-order fallback.

## Required handling

Use the owner-validated reader whenever it identifies an owner.
When the owner is unknown, use the plane handle only if no decoded principal plane has a vendor number.
The handle still requires the decoded principal plane's axis and complete frame to match.
Otherwise keep the stream-order fallback.
The [placement process check](../../../../../re/solidworks/FeatureLadderRecovery/CheckPlacement.py) covers the vendor cases.
The generated pocket, signed Top rectangle and Top corner reader tests in `tests/Convert/Solidworks` cover the generated cases.
