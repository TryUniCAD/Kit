# An external origin point belongs to the user sketch

The first three-driver SDK anchor observer expected one coincidence entity to be the same COM object as `Point1@Origin`. It stopped before editing despite three clean opens, fully constrained sketches and one correct solid. The immutable failed result is SHA-256 `4fa47be9efb275bf5e8be234ca0213f20458a1ce2fdb7b3fc5627a774dc33547`.

The matched read-only probe then passed in four fresh processes between healthy controls, using the disclosed native original and identical generated candidate. Its result is SHA-256 `6e822733fe51dfb0aca6dfb91b5ec70500dff7c06a808fe2fc4d93c2c7411995`. Both initial and rebuilt states show two coincidence entities in the authored sketch: an external point with public Type 10, and the actual contour corner with public Type 0. Neither is the selected source-origin object. Each self-comparison and owning-sketch comparison succeeds. The selected model-origin point belongs to a separate sketch.

The native archive matches that distinction: the user sketch has a separate external point whose typed wrapper selects the actual origin feature and its point. A reference to an object does not make the referencing point the same native object.

Use the complete typed reference chain and actual owning-sketch/entity identities. Retain COM equality as an observation. Compare the local coincidence endpoint to the real contour corner and the external point to its own sketch. Verify the origin reference through the archive and require the real corner to remain zero through the independent driving edits.

`GetSketchPoints2` returned four contour points in both models; the legacy `GetSketchPoints` returned all five, including the external reference. Thus the newer enumeration cannot establish that the archive has only four point rows. The extra row must remain separate from contour incidence. [Existing point-collection boundary](../Model/Sketch/SketchPointCollectionsIncludeNonContourPoints.md)

Do not translate archive `sgPoint.fe4=6` directly into public `ISketchPoint.Type`: these are separate enumerations. The [2026 point-ID documentation](https://help.solidworks.com/2026/English/api/sldworksapi/SOLIDWORKS.Interop.sldworks~SOLIDWORKS.Interop.sldworks.ISketchPoint~GetID.html) also requires the owning sketch and entity type to identify an entity. Object equality zero means distinct, while two means unsupported in the [2026 equality enumeration](https://help.solidworks.com/2026/english/api/swconst/SolidWorks.Interop.swconst~SolidWorks.Interop.swconst.swObjectEquality.html?format=P&value=).
