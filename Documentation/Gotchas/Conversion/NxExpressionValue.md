# NX expression values do not drive geometry on load

## Expectation

Rewriting an expression value should change the model, because NX shows the new
value in its expression list.

## Observed behavior

Two different lanes hold an expression value:

- the expression record in the object-model section, which the reader sees
- the feature record's dimension table, which NX uses for feature dimensions
  such as `p0`, `p1`, and `p2`

`nx.expression_values` rewrites the expression record. For an independent
expression that is enough: `empty_expr.prt` written as `kit_len = 25.0` reports
`EXPRESSION kit_len 25.0` in NX 2506.

For a feature dimension it is not enough, and writing both lanes by hand is
wrong: a `p1` attempt produced `EXPRESSION p1 -44.0` because the handle pattern
also matched unrelated bytes. The override therefore refuses names that appear
as feature labels and points at `nx.body_length`.

Geometry is also not regenerated by any value edit. Driving dimensions are
cached in the feature record, and section 0 carries the body, so a part whose
dimension changes but whose body does not loads with the old volume.

## Workaround

Use `nx.body_length` for the driving dimension; it rewrites the body, the
`p0` handle pair, and the `p0` text together. Use `nx.expression_values` only
for independent expressions.

## Evidence

```
empty_expr.prt   kit_len = 25.0   -> STATUS 0, EXPRESSION kit_len 25.0
dim40.prt        p1 = 45.0        -> refused: cannot change a feature dimension
dim40.prt        nx.body_length   -> BODIES 1, p0 60.0, VOLUME 36000.0, MASS 0.28190304
```
