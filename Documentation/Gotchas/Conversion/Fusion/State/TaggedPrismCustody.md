# A broader prism view can change an existing document contract

## Expectation

Accepting topology entity identities in a specialized prism view only adds support for newly saved edits.

## Actual behavior

The broader view also accepts existing eight-byte, entity-tagged feature histories that previously remained `JournalModel`. A geometrically rectangular insertion does not establish that an existing document should change its history representation. Specialized prism emission uses canonical record order, while the complete typed journal preserves the source order and values.

The merge-group candidate `b6a3001875fc8e89d9161b96af5bb428b8bee670` failed existing journal-contract assertions and a prepared-archive byte comparison after this reclassification.

## Workaround

Retain complete typed journal custody for the established eight-byte, entity-tagged document profile. Admit the independently measured four-byte saved-edit profile without changing existing histories. Keep source-byte and feature-history compatibility checks active.

Scope drafted projection by both its source geometry role and supported plane and direction. Preserve diagnostics for the existing untapered, reverse, and datum readers; changing the parameter alone must not select a new geometry family.
