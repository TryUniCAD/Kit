# A recognized cold scaffold can retain an informational diagnostic

## Expectation

A strict read of an ordinary generated part can appear to require a document with no diagnostics.

## Observed behavior

The ordinary SDK projection retains an informational diagnostic for the recognized stock `Lights and Cameras` name record.
An arbitrary native graph with that diagnostic is not a qualified writer input.
Removing diagnostics or native metadata before qualification would discard evidence of unsupported source information.

## Workaround

The research adapter first regenerates the complete original archive and compares the complete cold SDK projection.
This comparison includes diagnostics, provenance, scaffold and derived geometry.
It also verifies the original archive digest and exact source bytes.
Only this complete match permits the bounded authored projection used for a depth edit.
Extra metadata, changed topology and research-qualified records must refuse reconstruction.

See the [SOLIDWORKS encoder adapter](../../../../../re/automation/EncoderRoundTrip/Solidworks.py) and the
[exact publication requirements](../../../../Changes/Solidworks/Construction/SolidworksMeasuredPartPublication.md).
