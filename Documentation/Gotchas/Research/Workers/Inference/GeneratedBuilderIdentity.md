# Generated builder identity on Windows

The first native builder-development pilot exposed two contract errors before any
model call. Python text writes translated the generated source's LF bytes into CRLF,
while independently frozen source identity used LF. The strict verifier correctly
rejected that mismatch. Write generated and registered C# with explicit `newline="\n"`;
hash the exact artifact before compilation and require that same frozen hash during
verification and registration. Do not normalize observations or weaken hash checks.

The trusted block prerequisite's actual `IFeature.GetTypeName2()` was `Extrusion`,
while the initial independent check incorrectly expected `Boss`. Both are distinct
documented strings associated with `IExtrudeFeatureData2` in the official
[GetTypeName2 reference](https://help.solidworks.com/2022/English/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IFeature~GetTypeName2.html).
Freeze the exact `Extrusion` prerequisite type for this installed build before new
generation. Continue requiring its extrusion interface, operation, end condition,
depth, order, parents, driving dimensions and geometry. Do not accept arbitrary
feature types or change numeric tolerances.

The failed pilot's source and expectations remain unchanged and its result remains
unqualified. A corrected verifier contract requires a fresh source-bound job and
fresh private qualification reservation. The wrong-support plane itself was valid,
editable and equal in mass; all three owned processes closed normally with healthy
controls and independently reopened saved states. That observation is not builder
qualification or decoder completion.
