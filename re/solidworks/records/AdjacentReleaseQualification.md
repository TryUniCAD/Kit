# Qualifying an adjacent SOLIDWORKS release

Keep one semantic model and qualify each release's read and write paths independently. Start with the 2026 SP05.2 archive and constructor evidence, its nominal document version 19000, and the current fail-closed schema guards. A format revision changes only rules that the target binaries and independent source files establish. [2026 binary manifest](../v2026/Manifest2026.json) · [CAD success criteria](../../../Documentation/Reference/Operations/CadSuccessCriteria.md)

1. **Pin the target and lock sources.** Record the executable file version and hash, COM ProgID and revision, loaded module hashes and architecture. Author matched controls in the old and new applications from the same neutral definitions. Include an empty document, simple parametric geometry, a feature or configuration variant that changes archive topology, an external-child assembly, and a drawing with a model view that can be updated. Hash and seal the target's held-out inputs before extending a writer family. Keep the licensed binaries and decompiled listings outside the checkout. [Loader analysis](../../Playbook/LoaderAnalysis.md) · [Generative corpus](../../Playbook/GenerativeCorpus.md)

2. **Regenerate and compare class inventories.** Use the existing vtable dump format and generator, passing additional `module=path` arguments for the other selected DLLs. Compare the same DLLs on both releases where possible. Treat changed targets and slot counts as places to recheck, and DLLs found in just one input as inventory coverage. Confirm the runtime descriptor and actual serializer dispatch in the pinned binary before translating a schema. [Map generator](../../tooling/sw2026/SerializeMap.py) · [2025–2026 map result](../v2026/SerializeMapDiff.md)

   ```sh
   python re/tooling/sw2026/SerializeMap.py /tmp/AdjacentSerializeMap.json \
     sldmodu=/private/research/adjacent/sldmodu.vtables \
     sldarchiveu=/private/research/adjacent/sldarchiveu.vtables
   python re/tooling/sw2026/CompareSerializeMaps.py \
     re/data/Serialization/SerializeMap2026.json /tmp/AdjacentSerializeMap.json \
     --output /tmp/AdjacentSerializeMapDiff.json
   ```

3. **Trace effective versions and context.** The SW container reader's `ContainerMo` reports a document version from `_MO_VERSION_*`. Confirm its storage and signature against the target's corpus and API. Pass the explicit version to the archive operations. The 2026 DSL substitutes 19000 for an unset version, and several owner schemas require ordinary version 19000. Preserve those guards until the new branch is classified. Trace the effective archive or configuration-local version separately, including `moBaseConfiguration_c.f9a8` and any `ctx["conditions"]` transitions. Check reader and writer field order, tags, widths and normalization at each reached branch. [Container version selector](../../../src/convert/adapters/solidworks/Container/Archive.py) · [Version predicates](../../tooling/sw2026/serial/Dsl.py) · [Configuration version evidence](Tupni2026.md)

4. **Carry verified rules into a release profile.** Keep the release's file marker, history stream paths, originating build/date and service-pack fields, and Parasolid version with its explicit target. The 2026 composer passes the nominal document version from `Core.py` through its store calls. `Metadata.py` derives the `Biography` and `History` stream paths from it, while `Model.py` supplies feature version, date, service and Parasolid fields. Validate `swXmlContents/KeyWords` framing and ids against freshly generated model/header ids. Compare `swXmlContents/Features` version information when that stream is in scope. Reuse the ordinary container and archive model where target evidence agrees. For Config-0, model headers supply direct object identities before references are serialized. Derive the ResolvedFeatures prefix from the resulting configuration map, then seed the mate list from the resolved map where the target implements the same handoff. Determine map scope, section lengths and count widths in the target binary and corpus. [Metadata construction](MetadataConstruction2026.md) · [Archive map construction](ArchiveMapConstruction2026.md)

5. **Demonstrate both compatibility directions at their real boundaries.** The existing `RoundTrip.py --link-config` checks linked stream identity and rejects versions other than 19000. Keep that baseline when adding a target-specific entry point. Extend the archive [linked round trip](../../../tests/Convert/Solidworks/Research/ArchiveLinkedRoundTests.py) and [rejection](../../../tests/Convert/Solidworks/Research/ArchiveRejectTests.py) processes, [fresh part construction](../../../tests/Convert/Solidworks/Research/FreshPartTests.py) and [assembly bundle construction](../../../tests/Convert/Solidworks/Research/Assembly/OccurrenceBundleTests.py) with inputs authored for each claimed target. Require complete schema consumption, matching seeded maps and rejection of unclassified targets. On independently generated held-out outputs, use a fresh pinned vendor process with healthy controls and record open, rebuild, feature tree, editable dimensions, body count, volume, area, centre of mass, save and reopen. Capture exact generator, input, output and measurement hashes. Keep runtime file-access and donor checks in the process gates. Update the production compatibility claim only for the read and write versions that passed their respective gates.
