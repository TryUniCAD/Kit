# Ordinary assembly XML indexes on SOLIDWORKS 2026

The reduced assembly archives opened and rebuilt in SOLIDWORKS without the XML indexes. Kit uses `swXmlContents/COMPINSTANCETREE` to select its assembly read path. `AsmDoc` then independently requires `swXmlContents/KeyWords` and the resolved feature stream. Missing component XML causes the public SDK to enter the part branch even for an `.SLDASM` path. Missing KeyWords fails after assembly convergence. [Adapter dispatch and assembly fields](../../../src/convert/adapters/solidworks/Core/Adapter.py) and [component tree decoder](../../../src/convert/adapters/solidworks/Assembly/Assembly.py).

## Model-fed instance tree

The first populated rung has one root assembly, one active configuration, one external part document and configuration, and at least one direct, visible, rigid occurrence of that same part. The empty rung has only the root and its active configuration. The XML index uses a separate object ID namespace. There is one graph definition for each model and configuration and one file record for each file, independent of placement count.

## KeyWords projection

The index root gets its internal assembly name and creation timestamp from the actual graph. The single Configuration row names the active configuration with its actual local ID and `Type="ConfigurationManager"`. All three native assembly configurations omit a material attribute. Top-level rows are grouped by element tag in `Feature`, `Reference`, `Sketch` order, then lexicographic decimal persistent ID within each group. The real feature projection uses the corresponding native role vocabulary. Reference planes use `Type="PLANE"`, the origin uses `Sketch Type="Origin"`, and each `Reference` uses the real occurrence ID/name and `Type` built from its child file stem plus `-`. In the synchronized derivative the generated child's title and file stem differ, which distinguishes that rule from the occurrence name. [Observed native ordering](../../../Documentation/Gotchas/Conversion/Solidworks/Archive/Assembly/AssemblyKeywordOrderDiffersFromResolvedRoots.md).

The native saved index has 22 `Feature` rows, one origin and one reference row per occurrence. The initial builder has 15 real Feature roots and one origin root. Ambient/directional lights, two annotation-note nodes, exploded views, and display-state rows are absent from that graph. The reduced index emits only the generated roots and occurrences. A full presentation round trip still requires those actual objects and their frame, locale and configuration semantics.

## Generated boundary and public reader evidence

`AssemblyRootProcess.py` accepts a top-level `include_xml_metadata: true` to emit both indexes and the child's canonical principal-plane and origin roles. The research builders accept the same keyword argument. An indexed empty assembly requires an explicit native file identity. Its guard and default public reader both report one definition, zero instances, and a valid document. The populated graph indexes two models, two files, three placements and one child definition. Both index ID lists resolve to the same `moReference_c` feature IDs, `[17,18,19]`.

The locked repeated request reproduced the initial assembly `0416a16b74e0fb58047142f85f75ed48a7e327ca31ee18e92ee4ecae454bdd37` and child `ab85815e519ee6a1da1f1dc47fa18a4c9dba8e1b8f30a9b2c0b8a98a3d4a4f99` byte-identically. The opt-in assembly `2e88cc7166a0fac42ae28e549ba7bebfe35ae6cec93ec82653b616af29ef2d91` adds the two named indexes, leaving all nine prior streams byte-identical. The opt-in child `18a5dda151b192702878fd9f0d110a3db16bab667ea5314ec542d98deb11d44a` changes only KeyWords. Both guarded construction paths recorded zero runtime data reads. The separately generated empty indexed assembly measures `71c4a9a0d12c168fa6657a1bfa61c28cc0ca28795fd8d9f2728db477d2de36c7` in the disclosed replay.

Public `open_document(path, include_brep=False, include_tessellation=False)` validates the populated assembly and the sibling child part. The model contains two definitions, one linked child document and three rigid occurrence matrices. Testing the matrices at `(1,2,3)` mm gives `(1,2,3)`, `(98,-4,3)` and `(16,47,3)` mm. The recomposed Front sketch is bound to its exact model-owned plane 14 through the complete archived handle. Its 7 mm blind join remains in the child history. The assembly reader reports incomplete native name-record attribution for Lights and Cameras and the first two repeated occurrences. The XML preserves their occurrence identity and placement. [Public process regression](../../../tests/Convert/Solidworks/Research/Assembly/XmlIndexTests.py).

The normal geometry request fails on the generated child with `SLDPRT contains no readable Parasolid payload`. In history mode the original child labels first failed validation with `sketch sldprt:sketch:18 references missing plane`. Changing only the plane labels to `PLANE` misclassified Front and mapped its sketch to Right. The vendor's `Sketch Type="Origin"` gives the reader the principal-plane boundary along with the three `Feature Type="PLANE"` entries. The independent exact `19000` support reader then resolves actual model IDs for all three principal-plane variants. [Part handle evidence](PrincipalPlaneHandles2026.md).

The earlier reduced binary assembly has native open, rebuild, synchronized save and fresh reopen evidence. The indexed assembly has guarded archive and public SDK evidence. The generated topology is still limited to one active configuration and direct rigid occurrences of one ordinary child. Display-state content, broader child geometry, mates and nested placements require their own evidence.
