## Independent pre-writer source method

[Source plan](../../tooling/sw2026/ConcentricSourcePlan.py) contains three disclosed designs and creates the two reserved designs only inside the Windows guest. The disclosed pair D01/D02 has identical part geometry and initial poses, differing in lock intent and names. D03 uses a nontrivial common rotation, anti-aligned cylinder axes and reversed selection order. H01/H02 are generated by `SystemRandom` on a fixed private guest drive, after the method hash is locked. Their designs, native bytes and detailed observations remain in that guest directory.

Every design independently authors a translated-centre, fixed-centre circle with a radial driver and a forward blind boss. Both real cylindrical faces are obtained from the actual child body, mapped through their own occurrences, and selected as faces. The observer records actual occurrence IDs, component-specific entity owners, reference selection enum, analytic cylinder parameters, persistent-reference digests, API alignment and the actual `LockRotation` property. Pointer equality remains diagnostic because the existing native control work demonstrates that corresponding COM objects can use different equality codes; actual component identity and geometry are still mandatory.

Independent formulas compute the two rigid poses, cylinder volume and area, both centres of mass, coaxial residual and the planned valid slide/spin/depth edits. The source phase changes axial placement, changes spin only for the unlocked cases, and changes the child's real boss driver. It saves the child first, verifies both occurrences resolve to that exact child, saves the parent, and exports independent STEP siblings. Separate processes reopen the original and edited native pairs, rebuild, check complete native trees and parameters, and verify all native and geometry sibling hashes.

Each case has five distinct native process identities: before control, author/edit, fresh source reopen, fresh edited reopen and after control. The final lock requires every phase, both healthy controls, unchanged native and geometry artifacts and the source/tool hashes. The control is the previously qualified part `c0472f9f42bf473a9073adb997180040b7767dfae93310610f77cff9509bec57`. No control stream, template, captured value or native artifact is an input to a writer. Vendor templates are used only by the native API source author and their hashes are recorded.

[Registered metadata probe](../../tooling/sw2026/ConcentricApiMetadata.py) runs before any CAD instance. It requires the exact 34.0 interfaces, enums, `AddMate5` shape, actual face/cylinder/reference APIs and Boolean lock property. If these prerequisites differ, the packet stops before CAD. Native authoring is serial and belongs to the root agent. A failed case stops later design exposure while the trailing control remains independent.

The [2026 entity-parameter API](https://help.solidworks.com/2026/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IMateEntity2~EntityParams.html) describes point, direction and radius entries in assembly coordinates. The packet tests that geometry against its own independently authored poses. The [2026 rotation-lock help](https://help.solidworks.com/2026/English/SolidWorks/sldworks/t_assemblies_mates_concentric_lockingrotation.htm) describes an additional rotational constraint; a lock-only pair therefore isolates an intent change rather than claiming that eligibility and enabled state are identical.

Excluded: datum axes and lines, circular edges, cone/sphere references, misaligned/linked mates, arbitrary configurations, flexible/subassembly references, invalid-pose correction and deliberately forbidden locked-spin changes. These are separate future proofs. The source-only valid-pose cycle cannot establish their behavior.
