## Load and synchronization limits

The reference primary vtable `0x4cf7a8b0` is bound by original RTTI to `moReference_c`; cell `+0x11b8` is `0x4b677350`. That pass-two owner can recompute runtime `+0x540` from the node name versus the external definition name, then conditionally require the actual reference ID in the opened assembly manager's override set at `0x4b677539`. This recalculation is **DotWorks-mode gated**. Ordinary mode skips that block. It cannot be presented as the already observed ordinary rename cause.

The actual assembly primary vtable `0x4ce69b30` is RTTI-bound to `moAssembly_c`; cell `+0x14f0` is `syncRefNamesWithXModel` at `0x4b6b8880`. That routine independently reads environment option `0x72`, DotWorks state, runtime reference `+0x540` and external-object override state. The ordinary branch at `0x4b6b8b0c`–`0x4b6b8b4f` can reach the name-difference test, but the exact runtime cause remains unobserved. The complete public `IComponent2.Name2` setter-to-native mutation join also remains open. No generated override stream or flag patch is justified by this record alone.

The original registered metadata already binds `IComponent2` IID `{655D6F2A-5441-45D1-8CBA-D35FB26988E4}`, `Name2` DISPID `59`, getter invoke kind `2` returning BSTR, and setter invoke kind `4` taking one BSTR.
