## Safe recovery

Use `recover` only if the owned observation died or restoration failed. The command requires this exact packet's durable `Captured` and `Armed` records, both naming original true and the same exact owned oracle identity. It never guesses a value, attaches to a live process or changes another preference.

Recovery first requires an idle oracle; `Swapp.sweep` raises if any CAD process survives and kills none. The root owner must resolve the old owned process before recovery. A fresh exact-build application with zero documents records the current value, restores only the captured original true if needed, verifies it and closes. Recovery does not resume the observation or count toward the three-process result.

Recovery's code/metadata integrity check is separate from the measurement's CAD-input checks. Missing or changed source files cannot block restoration of an already armed preference obligation. It verifies the frozen Python closure and registered metadata, then the durable original-value records. `verify-recovery` validates only the tools; it performs no restoration, does not open CAD payload files and does not establish that a live recovery is possible without the required journal.
