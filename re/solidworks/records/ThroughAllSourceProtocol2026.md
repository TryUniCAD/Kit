The first three are inside-profile cuts in forward, reverse and both directions. The next three are bosses whose circle crosses exactly one stock side, also in forward, reverse and both directions.

## Independent geometry

For a stock of width `w`, height `h`, thickness `l` and center `(x,y,0)`, let `V0=w*h*l` and `A0=2*(w*h+w*l+h*l)`. A cut circle has radius `r` and center `(cx,cy)`.

The one-direction cut removes a cylinder of span `l/2`; its centroid is `(cx,cy,+l/4)` for forward or `(cx,cy,-l/4)` for reverse. The two-direction cut removes span `l` with axial centroid zero. Final volume is stock volume minus removed volume, and the center of mass follows the corresponding difference of first moments. A one-direction pocket has area `A0+2*pi*r*(l/2)`, while the both-direction through-hole has area `A0-2*pi*r*r+2*pi*r*l`.

The independent local-to-world frames are Front `(u,v,n)`, Top `(u,n,-v)` and Right `(n,v,-u)`. The actual native sketch frame is compared with those rules before comparing mass properties. Numeric geometry uses the existing source recorder's six-significant-figure gate and explicit near-zero absolute tolerances.

The finite axial span of a through-all boss is not yet bound. Boss cases capture native geometry and verify one positive merged body, valid operation history, live stock edit, clean save, immutable fresh reopen, and exact source/reopen mass equality. They retain `analytic_geometry_qualified=False` and `boss_extent_qualified=False`. A passing source lock cannot grant boss writer admission. The separately reported stock-span cap hypothesis is discovery data only and is not fitted or used as an acceptance target.

## Serial execution

Use [PrepareThroughAllSources.py](../../tooling/sw2026/PrepareThroughAllSources.py) to create an unused out-of-checkout packet from the pinned disclosed control, static binding and custody record. Python 3.11 or later is required on the host. The guest recipe uses the verified Python 3.12 launcher by default; an explicit existing interpreter can be passed to the preparer.

For a retry, supply the original `--previous-packet` and `--previous-packet-sha256` to the preparer. Only public seal metadata is read on the host; the guest seal verifies and copies the exact opaque container without design regeneration.

1. Run the frozen verifier on the host and guest. It reads only tool identities, the disclosed control, static binding, custody and disclosed neutral cases; it imports no COM or CAD runtime. Its namespace guard rejects a subclass method shadowed by actual inherited initializer state.
2. Run `D00 metadata`, which checks both registered version-34.0 type libraries, actual interface ownership, extrusion/cut signatures and the four selected end-condition enums. It launches no native application.
3. Run `D00 seal` on the fixed guest drive. It creates the new opaque four-case neutral container, with zero writer outputs.
4. For one requested case run `before`, `author`, `reopen-source`, `reopen-edited`, `after`, then `lock` as independent bounded commands. Each native phase gets a fresh process and exact executable identity. Always run the trailing control independently even after a preceding failure.
5. A lock requires all five healthy phases, chronological order, five distinct process creation identities, unchanged original and edited native hashes, and no errors, warnings, dialogs or cleanup diagnostics.
6. Disclosed detailed records are copied only into their own declared `Disclosed/Dxx` subtree. Hidden detailed records stay on the fixed guest drive. A failure stops later case exposure. Existing output directories are never reused or overwritten.

The metadata and source tooling is a discovery harness, not the conversion writer. It may use the native registered part template solely to author vendor sources. The future writer must emit all bytes from rules without that template or any CAD application.
