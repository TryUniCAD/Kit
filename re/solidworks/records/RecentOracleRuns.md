# Recent SOLIDWORKS oracle runs

SOLIDWORKS Design Premium 2026 SP5.2, Parallels Windows 11, 2026-11-14.

The host share `\\Mac\Home` is mapped to `Z:` in the guest. Generated files were written to
`Z:\Documents\UniCAD\Kit-solidworks-native\.rescratch\polyline`.

## Additive box

`OracleBox.SLDPRT` was generated from
`re/solidworks/examples/FreeCAD/AdditiveBox-1.1.4.FCStd` through
`write_document(..., allow_carrier=False)`. `OracleDrive.vbs` edited `D1@Boss-Extrude1` to
13 mm, rebuilt, and measured:

```
EDITED_REBUILT=True
EDITED_DEPTH_PARAMETER=13
EDITED_VOLUME_MM3=7800
EDITED_AREA_MM2=2500
```

Expected for 20 x 30 x 13: volume 7800 mm3, area 2*600 + 2*(20+30)\*13 = 2500 mm2.

`re/solidworks/examples/Single Turbo Dual Overhead Cam V8 - KDP - 2024/BLOQUE V8.SLDPRT`
and writing it with `allow_carrier=False` (`native-exact`, 736673 bytes). `OracleOpen.vbs`

Three more rewritten V8 parts were opened individually with the same script:

## Triangle depth edit

`OracleTriangle.SLDPRT` was generated from a three-line 42 x 31 triangle with 13 mm depth.
`OracleDrive.vbs` edited `D1@Boss-Extrude1` to 13 mm, rebuilt, and measured:

```
EDITED_REBUILT=True
EDITED_DEPTH_PARAMETER=13
EDITED_VOLUME_MM3=8463
EDITED_AREA_MM2=2840.95104346666
```

Expected: volume 0.5*42*31\*13 = 8463 mm3.

## Drawing fixtures

`AuthorDrawings.vbs` created three one-sheet drawings from the tracked five-line
part fixtures in SOLIDWORKS Design Premium 2026 SP5.2 (revision 34.5.2):

```
VIEW=standard Drawing View1 TYPE=7 X=0.11 Y=0.23
VIEW=standard Drawing View2 TYPE=7 X=0.22 Y=0.11
VIEW=standard Drawing View3 TYPE=7 X=0.11 Y=0.23
VIEW=standard Drawing View4 TYPE=7 X=0.22 Y=0.23
REBUILT=True
READ_VIEW=standard Sheet1 TYPE=1
READ_VIEW=standard Drawing View1 TYPE=7
...
DRAWING_SAVED=...\standard.SLDDRW EXISTS=True READ_VIEWS=5
```

`minimal.SLDDRW` was saved with two views at 2:1 and `angled.SLDDRW` with three
views at 1:1. The files are tracked under `re/solidworks/examples/Drawings/`.
The container stream list and reader behavior are documented in
[the drawing reader change entry](../../Documentation/Changes/Solidworks/SolidworksDrawingReader.md).

### Multi-sheet drawing

`AuthorMultiSheet.vbs` created a two-sheet drawing in the same installation. The
API reported `NEW_SHEET=True`, one view on `Sheet1`, one view on `Sheet2`, and a
successful rebuild and save. The tracked copy is
`re/solidworks/examples/Drawings/multisheet.SLDDRW`. It exposed a real
`Sheet Format` keyword entry that is not a drawing sheet; the stream layout and
reader handling are recorded in
[the sheet-format gotcha](../../Documentation/Gotchas/Conversion/Drawing/SolidworksSheetFormatKeyword.md).

### Projected view drawing

`AuthorProjected.vbs` created a base view (`Type=7`) and selected it before
`CreateUnfoldedViewAt3` produced a projected view (`Type=4`), then rebuilt and
saved `projected.SLDDRW`. Both views carry the parent model path in
`swXmlContents/KeyWords`; the tracked copy is
`re/solidworks/examples/Drawings/projected.SLDDRW`.

### Large and co-located view positions

`AuthorLargeSheet.vbs` created a sheet with a view centre at `(1.10, 0.40)`
metres and `AuthorCoincident.vbs` created two sheets whose views share the centre
`(0.11, 0.23)`. The reader returns both positions exactly:

```
large       Sheet1 View1 1.10,0.40
coincident  Sheet1 View1 0.11,0.23
            Sheet2 View2 0.11,0.23
```

The 384-byte paired-record rule and the no fixed coordinate bound are recorded in
[the position-record gotcha](../../Documentation/Gotchas/Conversion/Drawing/SolidworksDrawingPositionRecords.md).
