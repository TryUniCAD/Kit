### Recovered model edges

`Contents/VBLists` view sections are delimited by UTF-16
`model@Drawing ViewN` strings. The first count of at least two before the next
view name selects a block; edges start 20 bytes after the count and repeat every
204 bytes as six doubles. The recovered counts match the API:

```
standard  View1 5  View2 7  View3 7  View4 12
angled    View1 5  View2 7  View3 10
projected View1 5  View2 7
```

`minimal` and `large` do not expose a complete block and are rejected when edges
are requested.

### Recovered view orientation and sheet space edges

`OracleOrient.cs` dumps `View.GetViewXform` for every view. The orientation
record in `Contents/Definition` is a unit direction, a one-byte flag, an optional
nine-double row-major rotation, a three-double translation, and a trailing
`1.0`. The front view stores flag `0` and omits the identity matrix.

`AuthorOrient.vbs` authored one-view drawings for `*Front`, `*Top`, `*Right`, and
`*Isometric`; only the front drawing has no matrix record. The recovered
matrices match `GetViewXform` for all four `standard.SLDDRW` views:

```
View1  identity
View2  [[1,0,0],[0,0,1],[0,-1,0]]
View3  [[0,0,1],[0,1,0],[-1,0,0]]
View4  [[0.7071067811865464,-0.4082040559113551,0.5773815451999837],
        [0.0,0.8165408118857499,0.5772877120855426],
        [-0.7071067811865488,-0.4082040559113538,0.5773815451999819]]
```

The sheet position is `view_centre + scale * (R^T * (p - model_centre)).xy`.
Projecting the recovered model edges with that rule reproduces the typed C#
`View.GetPolylines5` edges for `standard`, `angled`, `projected`, `multisheet`,
and `coincident` with zero residual after rounding to nine decimals. The
`multisheet` and `coincident` inactive-sheet views are not returned by
`GetNextView`, so only their active-sheet views are compared.

### Custom view scale

`AuthorScale.vbs` set `View.ScaleDecimal = 3.0` on a single front view. The
position pair stores `1.0` on the primary record and `3.0` on the twin, so the
view scale is recovered from the twin rather than assumed to equal the 2:1 sheet
scale. The recovered sheet edges match the typed C# `View.GetPolylines5` edges
with zero residual after rounding to nine decimals, and the horizontal padding
stays at 0.004318 m.

### Written view position and scale

`WriteDrawing` rewrote the `orient-front.SLDDRW` view record from
`(0.11, 0.23, 2.0)` to `(0.15, 0.20, 3.0)` and the four `standard.SLDDRW` views
to `(0.05, 0.10, 1.5)`, `(0.11, 0.13, 1.5)`, `(0.17, 0.16, 1.5)`, and
`(0.23, 0.19, 1.5)`. SOLIDWORKS opened both written files and reported the new
values through `View.GetXform`:

```
written-front     GetXform=0.15,0.2,3
written-standard  View1 0.05,0.1,1.5  View2 0.11,0.13,1.5
                  View3 0.17,0.16,1.5 View4 0.23,0.19,1.5
```

`View.GetPolylines5` still returned the 75 edge doubles for the written front
view. The writer is bounded to the recovered position and scale records; it
retains the source document-level streams and does not change the orientation.

### Written negative position and renamed view

`WriteDrawing` rewrote the `orient-front.SLDDRW` view to `(-0.05, -0.02, 1.5)`
and renamed the `Data` view to `My View`. SOLIDWORKS opened the written file and
reported `GetXform=-0.05,-0.02,1.5`, so a view outside the sheet rectangle is
accepted and the record is matched by the source position rather than the name.

### Written origin position and reordered data

`WriteDrawing` rewrote the `orient-front.SLDDRW` view to `(0.0, 0.0, 1.5)` and
SOLIDWORKS reported `GetXform=0,0,1.5`. Reversing the `standard.SLDDRW` view
tuple before writing produced the same per-view positions as the natural order,
because views are bound to the source by name.

### Definition feature tree and model reference

`DefinitionGrammar` parsed and re-serialized the `Contents/Definition` feature
tree and model reference byte-exactly for all ten tracked drawings. The feature
tree holds 14 to 38 records; the model reference names `poly5a`, `poly5b`, or
`poly5deep`. `renamed-ref.SLDDRW` replaced the model reference name with
`poly5x` and SOLIDWORKS opened it with the same view position.
