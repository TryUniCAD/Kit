## Native phase boundaries

Each case has separate `ControlBefore`, `Generated`, `Reopen` and `ControlAfter` commands. Every command creates a fresh application, verifies the exact 2026 SP05.2 executable/version and requires zero documents before opening the parent. The after control has no prerequisite on the other phases, so root can still run it after a candidate failure or transport interruption. Existing output directories are refused. Partial records and missing phases never summarize as a pass, and an empty cohort cannot pass. The recipe carries an explicit phase order; acceptance also requires strictly increasing native process birth times across before, generated, reopen and after.

The original generated file identities point into their frozen `Generated` directory. A copied parent would still resolve that encoded child. The observer therefore opens the immutable original pair read-only and measures initial/rebuilt state. It then uses native child-first SaveAs to relocate the actual loaded child and parent into a new owned directory. Both occurrences must resolve to that exact new child before any edit. It changes the actual child depth parameter, rebuilds child and assembly, verifies independent geometry and identities, saves the owned child before the owned parent, and checks a fresh read-only reopen in another process. Original inputs and source controls remain hash-bound and must be unchanged.

Read-only SaveAs relocation is a deliberately unmeasured native path. A rejection is retained as a failure, not bypassed by patching files, preloading a child or weakening path checks. The reopened child stamp is checked on initial open against the saved stamp. Rebuild-time in-memory advances are recorded separately, following the existing qualified paired observer rule.

## Actual measurement and ownership

The wrapper reads actual native component names, IDs, configurations, fixed/visible/suppressed state, transforms and resolved child paths. Every occurrence must resolve one actual visible child solid. The shared cylinder check requires exactly one real cylindrical face and two caps. The shared mate capture verifies the one real active concentric feature, alignment, rotation lock, ordered face references, actual occurrence/component IDs, cylinder radius, coaxial geometry and nonempty persistent-reference evidence. Corresponding COM equality codes remain diagnostic, matching the existing native-control policy.

Every document must have zero `GetWhatsWrongCount`; every traversed feature must have zero error code, no warning and no suppression. Full trees are compared node by node. Both live radial and depth dimensions must be driving and writable; diameter is not confused with radius. Volume/area use relative tolerance `2e-7` and absolute floor `1e-15`; center of mass uses `1e-12 m`. Both configurations, authored matrices, fixed anchor and endpoint order remain explicit. Native mass is recorded but material-density parity is not newly qualified.
