## First source lock

Run [AuthorDrawingSources.py](../../tooling/sw2026/AuthorDrawingSources.py) in the pinned VM from the oracle owner's macOS controller. Supply a new output directory outside the checkout, the known-good independent native part control, the generated single-solid `.SLDPRT` and the installed drawing template. Hash all three inputs and the job specification. Choose a drawing template with one named sheet, zero model views and enough paper area for the requested locations. The author opens a private byte-identical copy of the generated part read-only. It creates the drawing with `NewDocument` and its optional model view with `CreateDrawViewFromModelView3`, then measures the requested scale and view position through a typed `IView`. Native traversal starts at the sheet sentinel and advances once before counting actual model views. The author saves `.SLDDRW` via `SaveAs3` and reopens it read-only in a fresh process with explicit drawing document type `3`. Both phases require zero native errors, warnings, modal dialogs, and rebuild issues. The model view must resolve the precise reference path and configuration, expose a nonempty outline, and preserve the native model-to-view transform and child geometry across reopen. The reopen phase moves the view by an asymmetric offset, rebuilds, and measures the corresponding outline translation in memory. The native drawing and child hashes must stay stable. ## First disclosed observations

The first pinned run recorded clean save, fresh `OpenDoc6` status `0/0`, zero rebuild issues and healthy bracketing controls. The empty source passed both phases. Both front-view drawings resolved the intended part, configuration and geometry, then failed the harness's literal comparison of the recorded reference name. All three disclosed containers use format version `4` and expose the same 29 named streams through the existing container reader. `Contents/Definition` carries the drawing CLSID `83a33d34-27c5-11ce-bfd4-00400513bb57` and a new-class tag for `moDrawing_c`, schema `1`, at offset `0x24`. The drawing keyword heuristics miss all three. The CLSID and typed root together supply a document discriminator for this lane.

The sheet properties show ANSI A landscape at `0.2794 × 0.2159` metres with sheet-format enum `13`, `swDwgTemplateNone`. The empty sheet stays at 1:1. ## Correlation and portability

1. Inventory the container header and named streams from each disclosed drawing, then identify typed `Contents/Definition` roots and their map context. Confirm the root discriminator against both part and assembly controls.
2. Classify paper, sheet scale, projection convention, attached model and configuration, view kind, orientation, position and scale as authored inputs or derived values. Then correlate the empty, front and moved-front controls to establish field order, conditional types, map bases and generated identifiers. Record projection polylines, external-reference state, thumbnails, duplicated positions, and view cache bytes with their actual owner and lifecycle.
3. Require exact decoding and re-encoding of every load-critical stream with no opaque tail. Prove any omissions or computed neutral values on controlled vendor opens. An editable drawing requires parametric sheet and view records and the correct attached model. Cache geometry alone is insufficient.
4. Qualify multi-sheet ownership, additional reference models, projected/section/detail views, native dimensions, tables, annotations, and sheet formats through controlled family additions. Each family needs a source lock and independent edit/rebuild verification. The first cohort covers one sheet and one ordinary part view.
5. Keep each release's executable and serializer-map pins, archive and container versions, keywords, and reference resolution context separate. A release port must reverify drawing root guards and drawing-only streams alongside the shared model core. [Adjacent release qualification](AdjacentReleaseQualification.md)
