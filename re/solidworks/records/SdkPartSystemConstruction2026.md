## Construction contracts

`MakePartRefs` accepts `StyleInput` and two `UnitInput` values. It generates
fresh style fields, document and analysis tables, model visual state and ten
independently owned views. These actual dependencies become `PartRootRefs`;
the existing root constructor preserves their identities.

`MakePartSysMut` consumes the validated `PartRootInput`, `PartRootRefs`,
`ManagerInput`, `SystemInput`, `FeatureTarget` and shared `PersistentIds`.
It returns `PartSystem` with the same root, manager, configuration nodes, system
nodes, origin graph and ordered resolved roots. There is no runtime import from
`re/`, no template input and no private data lookup.

`ManagerInput` contains an authored display name, distinct named `ConfigSpec`
values and current configuration index. `SystemInput` contains the exact twelve
classified folder class/name pairs in authored order, names for X/Y/Z planes,
a cabinet and origin name, selected principal origin support, explicit plane
construction-state Boolean and creation epoch. Names must be distinct within
the selected system profile. The older notes-area alternative, live sections,
drawing owners, materials, equations and populated folder contents are outside
this constructor profile.

The ordered global allocation is part, authored folders, cabinet, principal
planes in native `z/y/x` creation order, then origin. The manager remains ID `-1`.
Configurations use their own zero-based manager namespace and consume no global
persistent IDs. Every actual allocated feature appears once in the returned
feature sequence. Counts and IDs derive from these objects and the real
allocator, including explicitly reserved IDs.

## Stream and runtime ownership boundaries

The fresh part's `f2f8` stays null. `CMgr` is an independently rooted archive
with map base one, containing its own actual manager and configurations. This
component does not add an unproved manager pointer to Config or merge the two
maps. The current configuration is exposed through the actual manager aliases.

The fresh concept feature list remains empty. The returned ordered system
feature roots compose the ResolvedFeatures stream, continuing the exact Config
map snapshot. This is the existing cold construction policy, not an emulation
of all UI insertion/reordering callbacks. Native generic insertion, automatic
order changes, geometry operations and final save state remain distinct work.

Environment `f1e0` is the actual cross-stream alias. Runtime-only caches are
returned as `SystemNodes.RuntimeCaches`; the equation folder/relation manager
also retain their mutual symbolic references. These do not add archive bytes.
Raw decoding does not synthesize the feature `owner` or ordinary sketch `f138`
backlink. Independent preparation follows the origin's serialized component
reference to the actual part. The short point handle stores index zero and
correctly omits its `f18` extension.

`MakePartHeader` creates an SDK-native `moHeader_c` with typed Unicode string
owners, a schema-zero `su_CStringArray` for each name table and actual tuple-owned
log/stamp nodes. Its counter derives from the final graph. It can produce the
model-present header or Header2 without converting a research object graph.
Only the model has an initial creation log; the fresh planes therefore use the
native no-log reference-time branch. Additional per-feature logs, external file
identity and nonzero license/reference metadata need their own construction.
