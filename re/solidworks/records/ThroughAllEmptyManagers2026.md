## Typed construction and refusal

`EmptyMgrInput` holds an explicit BOM presence boolean and the existing shared `AppearanceState` contract. That contract's historical namespace is drawing-specific; its pure presence/unsigned64 state and signed-word decoder are reused unchanged, without relaxing its drawing reader or introducing another counter convention.

`ReadEmptyMgrs` requires an ordinary version-19000 schema-one part Definition. A present BOM must be the concrete schema-one `moBomInfoMgr_c`, with exactly its count/list fields, integer zero count and genuinely empty rows. Rendering presence must be exact integer zero or one. Presence one requires the exact three manager fields, exact empty reference-list fields and valid signed32 halves. Missing, unknown, populated, null-row, boolean-count or inconsistent state refuses. Presence zero refuses an unexplained body. The source-specific `ReadThruMgrs` additionally retains the full part and actual Config/resolved ownership checks. The caller supplies the Definition from the same hash-bound source archive.

`MakeBomMgr` constructs a distinct actual manager node when requested and computes its zero count from the modeled empty list. `MakeAppearMgr` derives the two signed halves from one explicit unsigned64 state and derives the presence byte and list count. An absent manager with nondefault allocator refuses because the missing body cannot communicate that history. `MakeEmptyMgrs` combines only these newly generated fields.

`MakeThruMgrs` constructs the existing fresh source-view/configuration component and adds those fresh owners. It receives no native record, source file locator, captured row, raw bytes or recorded field program. Existing composers remain unchanged. A source counter is never substituted for a global default. No public registration, complete source return or native attestation is added.
