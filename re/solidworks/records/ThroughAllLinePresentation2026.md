The current serializer's two passes at `[0x49ce4e30,0x49ce4f44)` exclude keys containing a wide star. The persistent component refuses these keys rather than silently losing requested categories.

## Map order

The original MFC file is ARM64X. Its raw export table does not identify the reached AMD64-compatible operation. The existing independent helper applies the declared relocation view in memory only; the ledger records 1,735 fixups and both hashes. Effective UI imports bind MFC ordinals 542, 8205, 1636 and 5960 to constructor, lookup, insertion and walk. Reached bodies are ARM64EC; no vendor code is executed.

The constructor stores seventeen buckets, independently of block-allocation default ten. Lookup samples UTF-16 code units at stride `floor(unit_count/10)+1`. Hash starts at `0x811c9dc5` and updates unsigned `((hash*0x1000193) xor unit)` for each sampled unit. Equality is `wcscmp`. New keys prepend to a bucket chain; iteration scans increasing buckets and follows chain next pointers.

Source projection reverses the compatible transmitted category sequence to obtain a valid constructor insertion plan, recomputes the native walk, and refuses a mismatch. This does not recover original runtime call chronology. Independent inputs specify their own insertion order. SDK code contains no saved category-order or default-row vector.

Font selector strings need not name local style objects. Both disclosed sources contain a selector without such a row. Native style lookup uses an ordered case-insensitive UTF-16 prefix comparison and can return `-1`; wider renderer/session resolution remains separate. This component neither invents a style nor saves an inferred display index.
