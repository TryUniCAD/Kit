## Retained observer failure

The first observer required one coincidence entity to be the same COM object as the selected model-origin point. It opened the same candidate cleanly in three fresh processes and observed one correct fully constrained solid, but stopped before every edit at that assertion. Its false result is retained as SHA-256 `4fa47be9efb275bf5e8be234ca0213f20458a1ce2fdb7b3fc5627a774dc33547` with healthy controls, no driving edits and no save credit.

The next [read-only owner probe](../../tooling/sw2026/InspectCornerPointOwners.py) compared the disclosed native original `7dc2a38554ccdbdd0ec56cf9bdf22d67f789a2922760c2d3cdc82a8d442ffefe` and the bit-identical SDK candidate. Its four-process result, SHA-256 `6e822733fe51dfb0aca6dfb91b5ec70500dff7c06a808fe2fc4d93c2c7411995`, passed with both controls. Each object's self-comparison returns one, and actual owning-sketch comparisons establish those domains. The two coincidence points expose IDs `[4,5]` and `[0,1]` in both specimens, but an ID pair alone does not identify an entity across sketches. The native source profile/origin feature IDs are `26/5`; the generated profile/origin IDs are `18/17`, as actually reported by COM and independently decoded from their archives. `GetSketchPoints2` exposes four contour points. The legacy `GetSketchPoints` exposes all five including the external point. The archive's fifth point row and typed wrapper select the actual origin without becoming that source-origin object. This refutes the old observer predicate; it does not refute the original file's geometry. ## Field terminology

Wrapper `f08=101` is the fresh constructor's last-access update stamp, not a point-selection kind or flag. The current native wrapper can refresh it from the owning model header. Wrapper `f0c` similarly moves from constructor `-1` to an actual active configuration ID. Those cache fields are distinct from the selected feature's `ff0.f08` creation-log time.
