# SOLIDWORKS 2026 sketch transform direction

The persisted sketch transform is model to sketch; the measured world-space
sketch basis is its inverse. The first readback check used the latter for both
roles. The original [failed remote attempt](../measurements/2026/TreeSavedReadbackAttempt856a.json)
passed all three Front-plane derivatives. The three Right-plane derivatives
each stopped at `frame_m2`: stored `+1`, compared against `-1`. The
[independent native receipt](../measurements/2026/TreeParityInspection01.json)
had already recorded both transforms from the API. Its model-to-sketch `m2`
is `+1` in each Right-plane phase; the inverse world-space `u.z` is `-1`.

## Reader rule and writer boundary

For rigid sketch-to-model row basis `B = (u, v, u × v)` and origin `o`,
the model-to-sketch row basis is `Bᵀ` and translation is `−o Bᵀ`.
The reader verifies that this formula equals the already measured
model-to-sketch API values, then compares those independent values with
the persisted matrix, translation and scale. No fixture bytes or neutral
targets change because of the corrected direction. The
[corrected remote readback](../measurements/2026/TreeSavedReadbackProcessesEfe1.json)
passes all six derivatives and every persisted transform comparison.

The frozen research generator's `Sketch.frame_transform` emits `(u,v,u×v)`
and `o` directly into `pd_ff0`. That matches identity but has the opposite
direction on the Right-plane input. The native application still opens and
rebuilds the measured output with the intended geometry; neither the exact
normalization boundary for the generated bytes nor arbitrary displaced planes
have been measured. This is an unresolved writer field. The frozen writer
and its historical receipts are unchanged, and full acceptance remains false.
