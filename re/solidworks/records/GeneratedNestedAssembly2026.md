# Generate a recursive native assembly research bundle

The stdin construction process produces a distinct native file for every definition in a neutral part/assembly DAG. The first candidate contains a dimensioned rectangular part, a subassembly containing that part, and a root containing the subassembly through a second noncommuting rotation. It generated three files with zero runtime file-access attempts and passed 28 object-stream round trips. A separate repeated mixed case passed two deterministic processes with four definitions, five definition-local XML occurrence rows and seven expanded paths. Native generated-output acceptance is pending. [Generation receipt](../measurements/2026/GeneratedNestedAssemblyBundle01.json)

## Authored request and supported profile

`NestedAssemblyBundleProcess.py` takes the checkout root as its argument and reads one JSON object from stdin. The object supplies a `root` definition ID and `definitions`. Each definition supplies its own `id`, `kind` and `request`. Part requests use the shared Part builder's neutral input, provenance, presentation, target and explicit native output identity. Assembly requests use the shared assembly fields, including their own file identity and single active independent configuration, and an `occurrences` array. Each occurrence supplies a unique sibling `name`, a declared target definition ID and a rigid `placement` with `origin`, `u` and `v`. The caller's definition order is independent of dependency order. [Guarded process](../../tooling/sw2026/NestedAssemblyBundleProcess.py) · [Recursive composer](../../tooling/sw2026/builders/NestedAssembly.py)

The admitted construction profile consists of reachable populated external subassemblies and ordinary generated polygon parts with forward blind extrusions. Every occurrence is visible, fully resolved and rigid, with its target's actual selected configuration. Unsupported occurrence state fields, mates and broader graph features fail the strict input mapping. Cycles, orphan definitions and colliding Windows file paths also fail. The first native predictor is further scoped to a corner-based rectangular prism on Front Plane with one independently authored depth edit. [Independent prediction](../../tooling/sw2026/PredictNestedAssembly.py)

The builder memoizes the generated document for each definition ID, so repeated occurrences share one native file and model state. Each containing assembly owns its own persistent-ID allocator, direct external directory and reference array. Directory entries preserve the first direct target order and count immediate users. They derive kind, path, creation time and the two save-time owners from the generated child. Per-occurrence configuration rows select `fc48` for subassemblies and `fc50` for parts, then copy those options into separate records. [Target-type and recursive stamp rule](NestedAssemblyReferenceState2026.md) · [Disclosed directory audit](DisclosedNestedAssemblyArchiveAudit2026.md)

Each reference gets the generated target's header update/time state and computed geometry/transform stamp pair. The assembly geometry stamp adds each target's accumulated geometry stamp to its own `f1300` modulo 2³². Transform uses the local-reference `101` sentinel fold. The shared configuration header builder now computes that same pair for an assembly's `Contents/CMgrHdr2`. The part route retains its geometry source and transform literal. [Shared target state](../../tooling/sw2026/builders/AssemblyTargetState.py) · [Configuration summary](../../tooling/sw2026/builders/ConfigurationHeader.py)

`f1560` follows the direct reference array. Configuration activity and both header component counts follow the newly bound recursive activity walk. Each `f370` is target-local. The parent folds placed direct child boxes and spheres in occurrence order. XML assigns one file/model identity per reachable definition, traverses each definition's local references once, and expands the hierarchy through those shared identities. KeyWords comes from the actual generated feature roots and each direct occurrence's target file stem. ## First candidate and reproducibility

The first authored prism measures `0.0234 × 0.0149 × 0.0068 m`. Its module placement is `Rx(19°)` at `(0.0123, -0.0041, 0.0057) m`. The root places that module using `Ry(-31°)` at `(0.0872, 0.0246, -0.0178) m`. LinkPlate, OffsetModule and TiltFrame are separate files. Their geometry/transform stamp pairs are `(101,101)`, `(202,102)` and `(303,102)`. Module and root activity counts are one and two respectively.

The independent predictor computes one visible body, volume `2.370888e-6 m³`, area `0.0012182 m²`, and root center of mass `(0.10193135679551986, 0.02643718166306058, 0.004281401771879965) m`. The planned depth edit to `0.0103 m` changes root volume to `3.591198e-6 m³`, area to `0.0014863 m²`, and center of mass to `(0.10107914517832522, 0.025867437392760553, 0.005699720080997768) m`. These expectations come from the neutral geometry and independent transform composition.

```sh
python -I -B re/tooling/sw2026/NestedAssemblyBundleProcess.py "$KIT_CHECKOUT" < "$NESTED_NEUTRAL_REQUEST"
python -I -B re/tooling/sw2026/PredictNestedAssembly.py < "$NESTED_PREDICTION_REQUEST"
```

The predictor takes an object with `bundle` equal to the neutral request and an `edit` containing its part definition ID and new `depth_m`. Native measurements can compare each loaded definition and each expanded path against its initial and edited predictions.

The normal SDK `open_document` history route read the generated root with three definitions and two instance rows and returned an empty validation result. Fresh guarded processes also preserved the existing single-occurrence parent and child bytes and the two empty baseline hashes. These checks supplement the recorded source lock that predates nested writer construction. The generated candidate still needs native open, rebuild, leaf edit, synchronized save, fresh reopen, and bracketing controls.
