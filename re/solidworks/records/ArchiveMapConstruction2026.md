# Cross-stream archive maps in SOLIDWORKS 2026

Status: **binary rule recovered; eight linked streams passed remote verification**.
This is archive bookkeeping, not persistent feature identifiers or writer acceptance.

## Native rule

`slduiu.dll` function `0x49724450` writes `Contents/Config-0`, then constructs
`useCacheArchive_c(model, archive, 2, 0)`. Before writing
`Contents/Config-0-ResolvedFeatures`, it constructs the same helper with state 1
and storage mode 0. It writes the resulting archive `+0x50` map count as the
resolved stream's u32 prefix and serializes the feature list.

`sldmodu.dll` constructor `0x4c010120` implements the cache handoff. State 2
copies the current archive into the model's cached archive at `+0x1020`.
State 1 copies the cached archive into the current archive. Its copy operation
is `su_CArchive::copyLoadArrayStoreMapFrom`.

In `swccu.dll`, `0x31a39210` copies the store map at archive `+0x58` when its
mode argument is zero. In load mode it copies the load array instead. Both
paths copy the schema map at `+0x60` and map count at `+0x50`. These are full
map copies, not a formula based on feature count.

Source evidence is the copied 2026 SP05.2 binaries identified in
[`Manifest2026.json`](../v2026/Manifest2026.json). The retained local decompiles
are `sw26gh/out/slduiu_defrefs.c`, `sw26gh/out/rf_uca.c`, and
`sw26gh/out/swccu_archive.c`. The three addresses above belong respectively to
those modules; they must not be rebased using a different DLL's image base.

## Research implementation

`Core.ArchiveMap` retains a map counter and typed class/object entries.
`Load.map_state()` and `Store.map_state()` snapshot the current maps.
Supplying a seed to the next archive requires its initial counter to match.
Store snapshots retain object references, preventing Python identity reuse
from changing a later stream's object map.

`ConfigPart.store_config_state` returns generated bytes and the computed map.
`ResolvedCore.store_resolved(..., seed=state)` inherits that map while keeping
the resolved stream's own output buffer. Model nodes remain pointers; no
captured indices, offsets, lengths, or source values are needed.

The linked research CLI mode loads the configuration before its resolved
stream, requires the resolved prefix to match the configuration map count,
and decodes/re-emits the resolved stream with that inherited map. Its process
integration check runs in remote CI only.

The resolved document context now derives part/assembly identity from the
configuration's root class and its MBSM flag from the actual configuration
manager `f658`. Native 2026 `moModel_c::loadResolvedFeatures` at `0x4b588c90`
copies manager `+0x658` into helper `+0x890`; the MBSM suffix additionally
requires a part model. A fresh manager's constructor value of zero must not
be replaced by the ladder's saved value of one.
