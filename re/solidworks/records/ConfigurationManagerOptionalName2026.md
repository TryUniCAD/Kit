## Minimal typed SDK boundary

`ManagerInput.NameValue` now permits explicit `None`. `InitNodeMut` admits that state only for an unregistered schema-one manager, in addition to its pre-existing unregistered reference-plane case. A global allocator with an absent name is rejected. Every previous named path is unchanged. `PartBuildInput.ManagerName`, normal preparation and registration retain their existing nonoptional contracts.

`ReadMgrName` distinguishes a real null field from a missing field, empty name object, wrong class and wrong schema. `ReadMgrIntent` projects only the witnessed ordinary name/configuration-directory/selector intent. It requires schema-one part configurations with ordinal local IDs, explicit descriptions/update epochs, matching directory/allocation counts and `f360`/`f368` identity aliases to exactly one actual directory object. Equal names or equal IDs never replace actual object identity. It refuses exotic selectors; this is a bounded projection, not a universal manager validity rule.

The source `f678` update value is an independent configuration input. In the four disclosed saves it is `631180800`, while source header/save clocks differ. This observation is not a factory seed and is never substituted for a current save epoch. Other original manager fields remain codec observations outside this intent projection. The helper does not assert full source admission or silently claim that those fields are represented.
