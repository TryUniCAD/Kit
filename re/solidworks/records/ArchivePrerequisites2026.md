## Independent check of the omitted buffer-start offset

The native capture's script is [the exact captured script revision](https://github.com/TryUniCAD/Kit/blob/ffa6b5d2faa440c3a8f9bff18889caa438726f92/re/tooling/tupni/Solidworks2026.js#L20-L24), SHA-256 `58048181fc3cefee93d14432f77936335fdd6ad4ad17e1b3f9ebf78a68fda816`. Its part hook observes the actual archive argument at `sldmodu!0x4c229a60`. The read-only 2026 L1 capture has zero host and producer drops, no script error, and a clean detach. The original native file digest is `c0472f9f42bf473a9073adb997180040b7767dfae93310610f77cff9509bec57`. The [ladder manifest](../v2026/corpus/ladder/Manifest.json) maps it to the committed redacted L1 file, SHA-256 `55e5a9840cc78a1d4b3ac4b8de3f37540695494e4d7a0edfb3cd3a2a876e2ac6`.

Decode that hash-checked Git blob through the existing container reader. Its Config-0 is 25,390 bytes, SHA-256 `e7e700d5b112e7d9d1b1297bac8149707e67d9aac2e3c6f890b4cb2f97b1e5b2`. Stream byte zero begins the new class descriptor for schema-one `moPart_c`: three u16 words followed by eight name bytes. The body starts at byte 14. In the native part-entry event, `end - start` equals 25,390, `cursor - start` equals 14, and the counter is 3. Thus the observed `+0x48` pointer independently matches the Config-0 buffer origin, alongside the cursor and end checks. The counter is at first root-body entry, before the one L1 direct header binding documented by the typed trace. The capture has epoch zero and deliberately leaves the absolute stream offset null.
