## Measure the native mate

The generated phase opens working copies at the encoded parent and child paths. It observes the unmodified load before forcing a rebuild. It requires two resolved, unsuppressed top-level occurrences and one body in each. The exact parent and both loaded child references must identify the expected physical files. It checks each fixed flag, active configuration, 16-word occurrence transform, and every recursive parent tree row against the expected order. The child's three principal planes, origin, sketch and extrusion must appear. Both documents must report zero feature errors and warnings. [Warning 32 observation rule](../../../Documentation/Gotchas/Conversion/Solidworks/Oracle/AssemblyOpenWarningThirtyTwoNeedsRebuild.md)

The observer reads the actual `IMate2` from the native mate feature and checks its kind, alignment, suppression state, and ordered `IMateEntity2` participants. Each participant must resolve to the exact child and an existing principal plane on the named occurrence. The `EntityParams` position and normal must describe that transformed plane. The separately computed placement residual and the mate entity residual each require an aligned normal dot product within `1e-10` of one and a plane offset within `1e-10 m` of zero. The direct `Reference` object comparison is a separate observation because that API returns a generic COM object. [Mate reference API](https://help.solidworks.com/2026/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IMateEntity2~Reference.html) · [Mate entity parameters](https://help.solidworks.com/2026/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IMateEntity2~EntityParams.html) · [Reference type evidence](../../../Documentation/Gotchas/Conversion/Solidworks/Oracle/PlanarMateReferenceUsesSelectionEnum.md)

The first generated pair has a corner-based `0.0317 × 0.0126 × 0.0089 m` child and identity placements at `(0, 0, 0)` and `(0.1074, 0, 0.0123) m`. Its independently predicted initial assembly volume is `7.109676e-6 m³`, area `0.00317476 m²`, and centre `(0.06955, 0.0063, 0.0106) m`. Changing `D1@Boss-Extrude1` to `0.011125 m` predicts `8.887095e-6 m³`, `0.00356903 m²`, and `(0.06955, 0.0063, 0.0117125) m`. The observer measures both child and assembly properties and all three driving dimensions after the edit, child rebuild and assembly rebuild.

After a successful edit, save the exact working child first and then the parent in place. Require an unchanged child SHA-256 and update stamp across the parent save. A new process must resolve the saved child at that path and stamp, open without errors or warnings, and retain the edited geometry, tree and mate through rebuild. The original generated files and native brackets remain read-only inputs. ## Observed result

The generated parent had two solid occurrences, a fixed `DatumPlate-1`, a floating `DatumPlate-2`, and the same ordered 25-row parent tree throughout. The generated child's 26 rows retained its authored presentation labels, principal planes, sketch, and extrusion. The measured initial assembly volume was `7.109676e-6 m³`. The depth edit changed it to `8.887095e-6 m³`, and the saved parent reopened at that value. The observer matched area, centre of mass, transforms and active configuration in every generated phase. Both `Save3` calls returned `[true, 0, 0]`. The child's update stamp was 162 at save, after the parent saved, and on the fresh reopen. Frozen generated and control files retained their original digests. [Native receipt](../measurements/2026/GeneratedCoincidentMateNative01.json)

Both `IMateEntity2.Reference` calls produced the exact occurrence-specific plane object in all nine control and generated snapshots. The plain feature wrapper compared unequal. `Feature.GetSpecificFeature2` compared equal through `ISldWorks.IsSame`. The ordered endpoint selections resolved to the physical child and both independently calculated plane residuals were zero. [Reference identity gotcha](../../../Documentation/Gotchas/Conversion/Solidworks/Oracle/MateDatumReferenceUsesSpecificPlane.md)

Typed readback re-encoded the separate mate-list stream byte for byte in both the generated parent and its native derivative. The mate retained ID `19`. Native save recorded `f0c=256`, `f3b8=1`, and update words `(19000, 2026306)` from initial values `1`, `0`, and `(0, 0)`. The occurrence solve states went from `[3, 3]` to `[4, 3]`. Their fixed inputs remained `[1, 0]`. Both occurrence child-update words advanced from `101` to `162`. These reads bind the changes to the combined native open, rebuild, edit and save sequence. The exact internal transition remains open. [Native receipt](../measurements/2026/GeneratedCoincidentMateNative01.json) · [Constructor rules](AssemblyCoincidentConstruction2026.md)
