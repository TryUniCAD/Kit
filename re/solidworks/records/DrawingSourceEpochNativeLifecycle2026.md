## Exact typed origin join

Five separately launched host observer processes inspect four pairs each: constructed input, initial native save, initial fresh reopen, edited save and edited fresh reopen. All 20 joins pass.

The [observer](../../tooling/sw2026/epoch_join/Tools/InspectEpochProfileChild.py) reads the complete Definition and re-emits it byte for byte. It reads the actual linked child Header → Config → Resolved graph and independent CMgr, headers and History. The [join rules](../../tooling/sw2026/epoch_join/Tools/EpochJoinRules.py) require:

- One actual concrete `moOriginProfileFeature_c` selected by the stored FRData id and its own creation-event lookup, with no source-name selection.
- Actual display folder, view and component-wrapper aliases within the Definition graph.
- The concrete component chain, reference chain and one actual external-feature target, with both target and backlink equal to the view's real internal reference.
- The exact declared native child path and this generated child's actual self path and creation identity.
- The actual concrete CMgr configuration-directory node, its local id/name, and both selected configuration aliases matching the real view selector.
- Independently parsed clock owners matching the packet-bound collector for the same exact input hashes.

The selected origin has observed id 17 and creation epoch 2592000 in all 20 states. The lookup derives both from the actual child and its log graph; neither becomes a generator default. The origin still has no own creation event. The component stamp also matches `101 + actual reference f3f0` in these observations; that equation remained diagnostic in the frozen join rather than becoming a new saved-word assumption.

The configuration is an actual schema-one `moPartConfiguration_c`, with observed local id 0 and both manager selectors pointing to that same node. Its wire fields have no generic `owner` field in these states. The proof therefore binds the selected node inside the independently decoded child CMgr and the physically identified child file. It does not invent a cross-map global part-owner pointer or equate object indices from different streams.

## Clock owners that update

The child `f48` remains modeled while the child is only read through the drawing. During its writable edit/rebuild/save phase, both child headers record a new update time. Child self `f60` and manager-header `f60` advance together. Each value lies inside the recorded native phase wall-time interval and is preserved on fresh edited reopen.

The drawing retains modeled `f48`, even through its declared view move. Its self save time advances at each native drawing save and is then stable through fresh reopen. It still has no separate CMgrHdr2 owner. Header `f48`, self save time and manager save time must remain separate inputs/owners.

The child log list grows from one root log to seven logs in the saved edit phase. The six added captions are Ambient, Directional1–3, Notes and Notes1___EndTag___. They accompany regenerated helper features; they are not six new driving-dimension edits. Their event times and the original root event remain intact on fresh reopen.

Applying the pinned `getLatestModificationTime` tail-selection formula to these raw events gives a later log-tail time than archive `f50`, and a different time from header `f48`. This is a calculation from the native getter rule, not a live getter invocation.
