## Durable owned-session journal

[ComponentNamePreferenceLease.py](../../tooling/sw2026/ComponentNamePreferenceLease.py) writes each journal file exclusively, flushes it and calls `os.fsync` before returning. The files are independent immutable phase receipts:

| Receipt         | Required position and information                                                                                                  |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `Captured.json` | Before any mutation: actual original Boolean, enum `18`, exact packet and owned application identity                               |
| `Armed.json`    | Before any mutation: restoration target and recovery requirement if no restored receipt appears                                    |
| `Applied.json`  | After the temporary setter, when needed: raw setter return and actual getter read-back, which must be false                        |
| `Restored.json` | From `finally`, before application close: actual before/after values, raw setter return, exact original target and equality result |

The lease changes only enum `18`; no other preference setter is called. It minimizes mutation when the actual value is already correct. Setter-call counts are retained even on failure. A failure during authoring or saving still executes restoration. Failed or unavailable restoration makes the phase fail and records that recovery is required. The existing controller closes only its verified owned application and never kills a pre-existing process.

## Recovery after process death

The frozen recipe contains a separate `recover` command. It requires the exact packet's durable `Captured.json`, a valid original Boolean and the pinned owned application identity. It calls the existing idle-oracle check, which refuses any surviving or foreign CAD process without closing it. Only then may it create a fresh owned application with zero documents, restore enum `18` to the captured original value, verify the getter, and close that owned process. It writes durable `Before.json`, `After.json` and a final result in a new recovery directory.

Recovery is independent of source acceptance. It does not resume a partially authored document or qualify failed source measurements. A missing durable capture refuses recovery rather than guessing the original setting. Root must resolve any still-live owned author session before invoking the idle-only recovery command.
