# Fresh cylinder endpoint identity boundary

Fresh concentric endpoint construction remains unqualified. Twelve host SDK processes pass for two independent circle parts, but their normal generated native files contain no actual kernel partition, output body atom or registered manager atom. A valid reconstructed cylinder face does not supply the saved persistent identities required by the ordinary concentric endpoint codec.

Task `B04-SW2026-MATES-CONCENTRIC/fresh-child-identity`; owner `assembly_occurrence`; delivery PR #121. The frozen SDK baseline is `a27e5eff3fa9d87f9ca56c5b07ba57661ae1bcc7` with a complete 4,668-file source fingerprint. Dependencies are the existing ordinary circle writer, the [concentric codec](ConcentricMateArchive2026.md), [actual face bindings](ConcentricFaceIdentity2026.md), [saved kernel correlation](ConcentricKernelFaceIdentity2026.md), and the [public reader](PublicConcentricMateRead2026.md). This tranche's exit is a reproducible source-only inventory of present and absent owners. Native endpoint generation, held-out qualification and registry activation are not its exit.

## Independent inputs and actual production path

The caller authors two neutral documents without native source files. F01 is a forward Front Plane diameter-driven circle, radius 4.783 mm, centre (3.46, -6.91) mm, depth 18.427 mm. F02 is a reversed Top Plane radius-driven circle, radius 8.9165 mm, centre (-9.283, 2.467) mm, depth 11.073 mm. Their explicit preparation epochs and final native locators belong to the private frozen requests. No disclosed native case value or hidden case is an input.

The generator calls the real `PrepareNative` path with each independently authored document, then calls the normal `convert.write_document` registry with an in-memory binary destination and an explicit final native identity. A strict audit hook forbids all file I/O, process launch and network connections during preparation and public writing. Required Python codecs and capability-walker code load before this boundary; no document is generated as a warm-up. Candidate generation repeats exactly within each process and in a second fresh process. The normal registry's writer clock remains real; its file hash may differ from the explicitly clocked candidate.

All four files per case are source-generated parts or independent repeats. Default and metadata-only public reads of the first candidate and registry output run in eight additional fresh processes. They preserve every native system/user history row; the observer does not strip the system rows to manufacture a one-feature document. Each full default read has one solid, three faces, two circular edges, two vertices and exact cylinder geometry. Volume and area agree with independent `pi*r*r*h` and `2*pi*r*(r+h)` formulas. The analytic centroid is a frozen prediction only, not a claimed mass-API measurement.

## Generic analytic encoding is a different boundary

The public reader's existing `BuildCircular` reconstruction returns model-owned analytic topology. Its lateral face has a `body-sweep-side` identity; it is not a saved native face wire index or persistent kernel `node_id`. The actual [circle reconstruction plan](../../../src/convert/adapters/solidworks/Core/TypedResolved/Geometry/Circles/ReadCircPlan.py) explicitly marks `native_kernel_identity=False`. The public diagnostic identifies the B-rep as reconstructed. The unextended body and side face have no native identity attributes.

For each default read the independent probe calls the existing `EncodeBrep(partition=True)` without `solidworks_feature_ids`, frames it with `EncodePartition`, and decodes it again. All four ordinary analytic encodes preserve topology counts under `SCH_1200000_12006`. Their trace calls `EncodeBrepModel`, `EncodeBrepBody`, `EmitVendorMut` and `EncodePartData` once. The blank and vendor-attribute branches are never called. No `FACE_ID_2001` or `ATOM_ID_2001` attribute path is written. The decoded face-order attributes are transport bookkeeping, not a newly established SOLIDWORKS persistent identity. These standalone streams are never attached to any generated part.

This probe deliberately does not pass `solidworks_feature_ids` to the generic encoder. The older [prism partition experiment](PrismPartition2026.md) already distinguishes an analytic cache from native feature activation and records the unqualified vendor-attribute path. Its controlled warning result remains that experiment's result; no new cylinder native failure or acceptance is inferred.

The [model-owned rectangular partition](GeneratedRectanglePartition2026.md) is useful prior art for actual topology/attribute allocation, node IDs, body atom ownership and rollback. Its complete projection is scoped to a rectangular prism and an exact activation state. A circular constructor must derive its own actual periodic topology, kind-51 surface ownership, side/cap identities, body registration, marks and history. Transplanting the rectangular IDs or reusing its graph because both have one body would not establish those rules.

The SDK and independently authored neutral spec stay unchanged. No native result or unsupported mate acceptance is reclassified by those corrections.

## Next construction obligation

The smallest missing output is a real generated cylinder kernel/atom owner bundle connected to the actual `PartCandidate`: actual side face, both caps, body atom, the face/body attribute chains and model/feature activation. The existing component, file, configuration, header and map constructors can then consume those actual owners. The concentric wrapper can derive the feature/epoch/marker terms, but must refuse absent face/atom owners and an unproved optional-vector condition. A neutral cylinder face ID or an isolated older-schema analytic stream is not an acceptable replacement. Native open, alignment/lock behavior, independent motion/edit/save/reopen and held-out evaluation still precede public writer promotion.
