# SDK Header epoch integration for fresh planar mates

`DatumTime` now accepts the actual standalone SDK Header log/stamp nodes as well as the existing object-body row view. It preserves the ordered native node identities and reads the real first matching event. Malformed lists, schemas, duplicate selected IDs and invalid epochs reject before mate/dimension allocation. This is a source-only API integration; native acceptance and public writing are unchanged.

## Cause and projection

The SDK Header decoder stores a list's items as a tuple of actual `ArchiveNode` instances. The object-body constructor uses rows such as `{"o": node}`. The former `DatumTime` path sent both through a row-only accessor. Supplying a standalone SDK Header decoded from the freshly generated child therefore failed at the first log with `planar mate graph expected an embedded record`. This was an internal view mismatch, not missing native wire grammar. [Original diagnostic and its unchanged limit](SdkDrivingDistanceConstruction2026.md#header-api-composition-boundary)

[`ReadLogItems`](../../../src/convert/adapters/solidworks/Archive/Construction/PlanarMates/ReadLogItems.py) projects these two API views to the same ordered actual nodes. A log-list owner must be schema-one `suObList`; a stamp-list owner must be schema-one `moLogs_c`. Each item must be the expected schema-one `moLogs_c` or `moStamp_c`. The collection must be ordered, and an explicitly retained body count must equal its actual size. The helper returns the original nodes and never copies or changes their fields.

`DatumTime` filters by the actual selected datum's persistent ID, rejects multiple matching logs, and reads the first event's unsigned 32-bit `f18`. A missing matching log or an empty matching log uses the independently mapped native unset epoch `2592000`. A malformed log is not treated as an absent log. Bool, negative and overflow epochs reject. Header/class declarations and timestamp widths are the existing [`HeaderClasses`](../../../src/convert/adapters/solidworks/Archive/Header/HeaderClasses.py) and [`HeaderFields`](../../../src/convert/adapters/solidworks/Archive/Header/HeaderFields.py) vocabulary; no new native field, default or vendor trace is introduced.

## Generated process cases

[`HeaderEpochProcess.py`](../../tooling/sw2026/HeaderEpochProcess.py) authors the same neutral distance bundle through the unchanged research publisher. A separate source-only history author adds a selected principal datum's log and two explicit events to both child header roles when requested, using the actual datum ID and native header codec. It regenerates the headers from their typed objects. It does not patch offsets or read a native input file.

The SDK lane passes either the original body header or the actual standalone SDK Header decoded from those generated bytes to the mate constructor. The independent reference lane keeps the established body view. Nine designs cover all principal axes with absent, empty and two-event selected logs. Their mate references must use the actual first event rather than the later event. Complete parent/child containers, every parent stream, the exact mate codec graph and the driving parameter readback compare across all three lanes. Returned log nodes must retain identity.

Twenty-four malformed cases cover twelve independent faults in both views: duplicate selected log, negative/overflow/bool epoch, wrong log/stamp class or schema, invalid collection, bad count, wrong list owner and malformed object row. All reject without advancing the shared ID allocator, assembly reference counter, header watermark or fixed flags. Permanent checks live under [`Mates/HeaderEpoch`](../../../tests/Convert/Solidworks/Research/Mates/HeaderEpoch/).

## Historical replay and shared extraction

The final verifier binds the shared eight-file common-dimension extraction before execution. Its manifest SHA-256 is `7171a9e2a023947c872f4e66192ae42ad36faf454741ba4aef6ccd7d60790b17`. The header lane changes no Dimensions source; the common extraction remains independently owned.

The first historical replay loaded a sorted canonical request and produced a different child. Re-running both the original and current frozen sources with that same sorted request reproduced the same different child, with identical logical streams. Reconstructing the original request from its unchanged author factory instead reproduced the published child exactly from both sources. Nested presentation mapping order had been lost in the archived canonical JSON. Neither a header/codec repair nor updated expected hashes was needed. [Existing ordering gotcha](../../../Documentation/Gotchas/Conversion/Solidworks/Model/Ordering/JsonObjectSortingChangesPartFolderOrder.md)

The verifier now checks the original request-factory dependencies against the old source manifest and regenerates their authored order, then requires exact canonical values against the archived recipe before replay. It preserves all old proof files and expected artifacts. Every new run saves and hashes the exact compact stdin bytes that it actually sends; its canonical digest is separately named. New header-case recipes also declare `folder_order` explicitly. The published twelve-bundle regression requires whole parent and child equality, exact parent streams, mate framing/map and typed readback.
