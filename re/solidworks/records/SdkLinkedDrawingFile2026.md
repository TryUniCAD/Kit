# SDK-only linked drawing file construction in 2026

The internal SDK now constructs a complete ordinary drawing around an actual SDK-generated rectangular part. The final offline cohort passes 43 isolated processes. This does not enable the public writer or establish new native or held-out acceptance.

## Task and admission

Task: `PR121-SDK-DRAW-LINKED-FILE`. Owner: `configuration_header`, with the PR #121 root owning native execution and the part lane owning `PartCandidate`. Delivery: PR #121. Dependencies: the frozen [blank-file constructor](SdkBlankDrawingFile2026.md), current shared part constructors, named-view Definition codec, header/metadata executors and the existing generative container writer. The exit condition for this slice is a fresh SDK-only complete linked graph, exact independent generated file parity, independent projection math, unchanged child reemission, explicit unsupported-input rejection and a frozen native-ready request.

`MakeLinkedFile(LinkedDrawInput, PartCandidate)` consumes genuine `DrawingData`, explicit native presentation/provenance/support names, and the original result of `MakeBlindPart`. It does not accept a decoded research graph, native file, recorded field program or byte template. The child remains the same actual object, with its real model, active configuration, model header, self-file record and configuration-manager header.

The profile is one active unformatted ANSI A landscape sheet, one external nonvirtual generated child, one ordinary absolute view, and an XY-aligned four-line rectangular forward prism. The four admitted names are `*Front`, `*Top`, `*Right` and `*Isometric`. View scale is an explicit finite positive scalar represented as `(scale, 1)`. Inherited view scale, other denominator representations, arbitrary orientations, other child shapes, additional sheets/views/references and contradictory supplied geometric caches reject. The named codec's broader typed ratio grammar remains separate from this constructor admission.

The neutral view's model-reference ID, configuration name and source path must identify the actual generated child. The qualified index profile also requires its model name to match the part basename. Returned source sheet/view/reference IDs retain the caller's mapping independently from computed native IDs. Unsupported content is not discarded while constructing the transient empty base.

## Projection precision and refuted implementation

The first local Isometric comparison found a one-unit radius mismatch at both `view.f600.b9` and its internal reference's `f370.b9`. All other streams and floating fields agreed. Python's generic floating sum produced `0x1.4a23bef8c6791p-6`; the existing independent constructor produced `0x1.4a23bef8c6790p-6` for the independently authored 29.3 × 17.9 × 21.1 mm prism.

The [native box helper](AssemblyConstruction2026.md#computed-geometric-bounds) explicitly computes `sqrt(dx*dx + dy*dy + dz*dz) * 0.5`. The new SDK helper now preserves that addition sequence. The earlier compensated-sum implementation is refuted for exact construction parity. Its failed development run stays private and does not count as acceptance. See the [specific gotcha](../../../Documentation/Gotchas/Conversion/Solidworks/Archive/Drawings/BoundingSphereUsesNativeAdditionOrder.md).

It verifies full Definition/header read and reemission, public sheet/view/model identity and transform semantics, and the unchanged reemission of every child stream after attaching its shared handles to the drawing.
