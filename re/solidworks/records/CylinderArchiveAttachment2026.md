## Guarded reconstruction

Two independently authored cylinders use the normal SDK's neutral-to-part preparation first. The experiment changes exactly the configuration, resolved feature, manager, manager header, two model header, and partition streams. It composes the container from those bytes plus the other in-memory streams already generated for that request.

Four fresh host processes, two per authored case, repeat the attachment exactly and refuse reattaching to the populated model. The SDK reads the same atom through all three archive routes, resolves its actual producing extrusion and arc, matches the selected persistent face, and checks the two mark IDs and manager update stamps. Build and readback make zero filesystem, process or network calls. [Generated attachment receipt](../measurements/2026/GeneratedCylinderAttachment01.json)

```sh
PYTHONPATH=src:re/tooling/sw2026:re/tooling/sw2026/serial:. python -B -m para.cylinder.CheckAttachment 1
PYTHONPATH=src:re/tooling/sw2026:re/tooling/sw2026/serial:. python -B -m para.cylinder.CheckAttachment 2
```

Both generated archives are research candidates. Complete runtime body and face allocation history, tessellation and geometry caches, actual SOLIDWORKS cold load, rebuild, driving edit, save and reopen, and use in a generated concentric mate remain open. This evidence credits zero native writes and zero held-outs.
