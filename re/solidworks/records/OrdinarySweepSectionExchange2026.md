# Ordinary sweep section sheet exchange on SOLIDWORKS 2026

The first two independently generated section transports are the 873-byte Parasolid sheets pinned by [the section transport measurement](../measurements/2026/OrdinarySweepSectionTransport01.json). `Section3773.x_b` is an origin-centred Right-plane disk with radius `0.003773` metres and SHA-256 `7a9e5e0b6e30805dacc82e2443eebe00100e0b05d6dcbca578ba126bbfe06637`. `Section5159.x_b` has radius `0.005159` metres and SHA-256 `2f3666f352e66181c5a2d7b1aa5fd522268499fe41624cb15b58fe85209fc31a`. The typed model has one face, one circular rim, and zero vertices in each file. The measured embedded source sheets have a nonresident `BODY.next` link. The standalone constructor derives a null link for its one-body graph.

[The guarded packet](../../tooling/sw2026/sweep_source/SweepSectionPacket.py) binds the exact tool tree, two generated payloads, and independently qualified pristine ordinary solid `c0472f9f42bf473a9073adb997180040b7767dfae93310610f77cff9509bec57`. Only the licensed root-owned Windows oracle launches SOLIDWORKS. Every phase must bind versioned COM and executable identity `34.5.2.0604`, SHA-256 `3f6844591c7456a476bdc141817a21c3c10f770e12347a698eef5ea8ad60d1fe`, with unique PID and creation time. The binary disk import uses `ISldWorks::LoadFile4` through the same ordinary translator and guarded 3D Interconnect setting used for the earlier cylinder exchange. [Parasolid import and export](https://help.solidworks.com/2026/English/SolidWorks/sldworks/c_parasolid_files.htm)

The before and after sheet controls are authored independently at their respective candidate radii. The native author sketches a circle at the origin on its actual Right Plane and selects that boundary sketch with mark `1` for `IModelDoc2::InsertPlanarRefSurface`. It records the installed 34.0 interface members and template hash, verifies the analytic disk, and exports it as `.x_b` using a fresh locator. Its matched import phase reopens the exact export digest in a separate process. [Planar reference surface contract](https://help.solidworks.com/2019/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IModelDoc2~InsertPlanarRefSurface.html) [2026 marked selection contract](https://help.solidworks.com/2026/English/api/sldworksapi/SOLIDWORKS.Interop.sldworks~SOLIDWORKS.Interop.sldworks.IModelDocExtension~SelectByID2.html)

The phase order is stock application control, first disk author and import, two generated exchanges, second disk author and import, and stock application control. Both candidate phases require the initial controls to pass. The terminal receipt verifies both bookends, all eight independent process identities, matching installed authoring methods, no rebuild diagnostics, restored preferences, immutable input hashes, and the idle process guard. Each cold and rebuilt import must expose one persistent sheet with its actual single planar face, one loop on the actual full-period rim, Right-plane station, area `πr²`, and the correct transverse extents. One real valence-two closure vertex is accepted as a translator representation when both rim ends identify it and its position lies on the measured circle. The observer records the actual seam inventory before and after rebuild and requires it to persist within each import. [2026 plane parameters](https://help.solidworks.com/2026/English/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.ISurface~PlaneParams.html?format=P&value=)

## Stage and run

Use an unused external packet, a directory containing the two exact `.x_b` files, and the pristine control. To regenerate the sheets from radius values, use `AuditSweepSectionTransport.py --emit-raw-radius-m` with the values above and redirect its standard output to each fresh file. `SweepSectionPacket.py freeze --revision REV --control CONTROL --generated GENERATED --output PACKET --guest-packet 'C:\KitSweepSectionExchange01\Packet'` copies the committed tool closure, verifies all disclosed inputs, and publishes the job digest. `PACKET/Tool/SweepSectionPacket.py verify --job PACKET/Job.json --pin PIN` confirms the frozen job on the host with no native execution.

From the licensed oracle, run the frozen tool via Windows CPython 3.12. Use the managed host share packet path for `stage-guest` and then the exact staged guest path for `run`.

```sh
prlctl exec 'Windows 11' --current-user 'C:\Users\odin\AppData\Local\Programs\Python\Python312\python.exe' -E -B "$SHARED_PACKET\Tool\SweepSectionPacket.py" stage-guest --job "$SHARED_PACKET\Job.json" --pin "$PIN"
prlctl exec 'Windows 11' --current-user 'C:\Users\odin\AppData\Local\Programs\Python\Python312\python.exe' -E -B 'C:\KitSweepSectionExchange01\Packet\Tool\SweepSectionPacket.py' run --job 'C:\KitSweepSectionExchange01\Packet\Job.json' --pin "$PIN"
```

Retrieve `C:\KitSweepSectionExchange01\Records\Result.json` after the oracle exits and verify the terminal digest. Keep native binaries and raw exports outside Git.
