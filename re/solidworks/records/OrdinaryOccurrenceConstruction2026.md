# Ordinary external part occurrences in SOLIDWORKS 2026

This record covers the ordinary, resolved, nonvirtual part occurrence in a single-configuration assembly. The native implementation is from SOLIDWORKS 2026 SP05.2, `sldworks.exe` build `34.5.2.0604`. Addresses are preferred virtual addresses in `sldmodu.dll`, SHA-256 `569a081928ad24afac5408cc15a1034d18e89b2c5001428a64115a3cc497067e`, unless another DLL is named. The disclosed A12 empty, A13 single-part and A14 repeated-part assemblies are identified by the [source manifest](../v2026/corpus/assembly-synchronized/Manifest.json). A15 and A16 remained sealed while deriving these rules.

## Generated single-occurrence process

The research constructor accepts the generated child part's self-file record, active configuration and configuration manager header. It creates a distinct child directory entry from that identity, places it after the parent self entry, then links Config-0 directly to slot 4. Directory `f60` comes from the child's self-file save event and `f70` from its configuration manager save event. The directory owns the occurrence count. Its configuration selector is absent. The occurrence owns the actual child configuration selector. Generated child documents without an explicit display-state entry retain the selected insertion options' display state.

The one-occurrence process derives the child's bounding box from the generated polygon's actual sketch coordinates and blind depth. The stored rigid transform uses the child's basis vectors in parent coordinates as rows and its origin in parent coordinates as translation. Both assembly boxes have corner extents in parent coordinates and independently transform the child's bounding sphere center while preserving its radius.

The [guarded integration test](../../../tests/Convert/Solidworks/Research/Assembly/OccurrenceBundleTests.py) generated one identity placement and one rotated, translated placement. The config, manager, resolved, mate and header checks completed in both processes with zero runtime file reads. Each generated assembly used the same independently generated child. Existing empty-assembly container hashes were preserved through the addition. Repeated-occurrence configuration ordering, mass-cache construction and other component states remain open. The disclosed source corpus was used for discovery. Native acceptance still requires controlled open, rebuild, edit and held-out runs.
