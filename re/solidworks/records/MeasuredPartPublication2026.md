This follow-up closes the ordinary public part publication boundary in
PR #235. The [original standalone native evidence](../measurements/2026/SdkDefaultPartNative01.json)
records the actual SOLIDWORKS 2026 SP05.2 executable identity and two
independently authored generated parts. That native run passed 240 numerical
checks across six fresh process lifetimes with healthy before and after controls.

The publication proof verifies the original terminal, packet, build proof,
six individual native phase records and two authored SDK requests against
their recorded SHA-256 values. It transfers the genuine evidence and exact
neutral requests into fresh guarded hosts. Each public write regenerates the
ten-stream archive and compares the whole output digest. The internal
preparer still derives the same bytes from the model alone. No report or
other input file is read by the SDK writer.

Both measured files reproduce through strict registry streams, direct writer
streams, actual staged host filesystem paths and the CLI. The non-Windows
path route retains the existing authored standalone Windows self locator
with the exact final basename. No new relocation rule applies to a
Windows target whose encoded path would differ. The matched output flags
are true after the gate. Both models retain their typed line loop, live D1
and exact polygon solid in normal readback.

Eight evidence and model contrasts per file fail through both direct streams
and the staged registry path. A ninth contrast fails when the stream
requests a different encoded locator. Those attempts leave the output
unopened. The old CLI candidate flag and a CLI request without
evidence also preserve existing bytes. The shared staging regression
reaches actual single-file publication and requires a populated directory
to retain its contents and original location.

An evidence report is unsigned. The host proof independently verifies
custody against archived digests. The production contract checks data
shape, exact oracle identity, measured phases and full output digest.
The caller remains responsible for obtaining an authentic report from the
controlled offline oracle. This follow-up introduces no native runs,
unmeasured successes or new held-out comparisons.
