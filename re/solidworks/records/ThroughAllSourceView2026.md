## Typed source composition

The existing `ViewInput` and `MakeViewPair` remain unchanged. `ReadViewPair` validates actual ordinary record modes, exact keys, an optional nine-coefficient orthonormal right-handed matrix, finite translation and positive scale. It returns only the immutable semantic view input. `CheckViewRep` requires that this input regenerates the exact source representation. Perspective, extra fields, a matrix on the pan/zoom owner, redundant explicit identity matrices and unrepresented affine state refuse. The byte comparison for affine scalars preserves signed-zero distinctions rather than normalizing unknown state.

`ReadThruView` retains the complete source checks and actual Config/resolved identity/order checks, then requires the ordinary version-19000 schema-one part Definition. The caller must supply the Definition parsed from that same archive. The frozen process method binds the actual source hash and extracts these owners in one read-only source process; the helper does not invent a hidden filesystem join or claim Definition has an encoded model ID.

`MakeThruView` first validates the semantic view through the existing pair constructor. It constructs the actual fresh source configuration/geometry component using `MakeThruConfig`, then assigns the newly constructed view owners to that fresh Definition graph. It never takes a native object, source field bag, raw span, source-file locator or recorded operations as writer input. Existing source/default composers are unchanged. No public registry or full-source gate is opened.
