## Why the radius relation appeared

The legacy `Core.Native.Constraints` circle branch uses `Profile.dimension_kind or "radius"` and appends a relation even when `parameter_name` is absent. That is a geometric inference from the circle's radius, not evidence of an authored solver relation. The complete native arrays and native owner graph show no radial dimension or fixed centre in these sources.

The current code already supplies the correction. `ReadLocalCirc(..., AllowFree=True)` accepts the exact empty local state and returns `LocalCircle` with no driver name/mode and no `NativeDimension`. The same call with its default free-state gate closed returns none. `CircleSketch` then projects the actual circle and centre entities, a closed circle profile, no constraints and no parameter IDs.

On the frozen published ordinary-blind path, `ProjectTyped` identifies the actual cut profile and supplies `AllowFree=True`. All three public `CutSketch` projections are therefore already correct. The old outside-worktree public baseline predates that cut-reader integration and must not be treated as current failure evidence. The internal legacy rule can remain available as legacy input evidence; the public typed projection does not use it as an actual constraint.
