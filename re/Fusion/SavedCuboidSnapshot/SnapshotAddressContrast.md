# Saved snapshot top entity address contrast

The `PassiveIdGenerator.addressOfTopEntities` sequence contains one address-like value for each ordered passive root. Captured values vary across saves. The experiment asks whether Fusion can regenerate them from a known saved cuboid's graph and snapshot. The snapshot contains a tool solid, a profile region and a sketch sheet.

Each cohort started with a healthy exact native archive. A typed repack retained complete parsed state while re-emitting history, snapshot and material parts. The zero-address variant changed only the three address values to zero relative to that repack. The typed snapshot, graph ownership and projected CAD semantics stayed equal. The repack and the zero variant form the single-field comparison. The exact original serves as an independent before and after health control.

## Native saved reconstruction

Every stage opened its own exact input in a fresh Fusion 2706.1.17 process. Each stage entered and exited with zero documents. The measurement covered open, compute, the local unedited export and fresh reopen of each export. Geometry, owner roles, feature graph and physical material matched. Separate strict SDK reads verified complete typed JSON equality and independently derived snapshots for every native export. A dedicated dialog watcher, visual presentation and selection were outside these measurements.

### Native save of a generated cuboid

The 21.3 × 33.2 × 15.9 mm cuboid retained volume 11,243.844 mm³. Fusion opened the all-zero variant, rebuilt the model and exported three distinct nonzero addresses. The three native exports allocated passive IDs `17,16,15` and next ID `18`. The inputs used `14,13,12` with next ID `15`. Each result bound the same roles to its newly assigned identities. The exact zero export reopened successfully.

## Scope of the rule

This compares an existing saved owner graph with and without its address values. An independently generated owner graph still needs its own fresh-process proof. The result does not establish a default for other snapshot types or the native treatment of invalid owner IDs. The [ownership seam](README.md) continues to require explicit address values until a fully generated archive is measured.
