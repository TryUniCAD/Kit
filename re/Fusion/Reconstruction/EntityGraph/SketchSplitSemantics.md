# Sketch split ordinals and direction wildcard

The two `sketch_tag_id` uint32 fields at offsets `0x28` and `0x2c` are a **one-based fragment ordinal** and **total fragment count**. Their native producer requires `1 <= splitSequenceId <= splitTotalNumber`. The constructor's `(1,1)` is an unsplit default, not the only valid serialized value.

The [native evidence](SketchSplitSemantics.json) references the binary hashes recorded in [SketchTagSemantics.json](SketchTagSemantics.json). The [read-only corpus report](SketchSplitSamples.json) was generated by [SketchSplitSamples.py](SketchSplitSamples.py). No native calls, production-code execution, or local tests were used for this study.

## Native meaning and invariant

`Ns::ASMInterface::split_sequence_id::debug` at `0xdc408` prints `sequence id` for the first uint32 and `total number` for the second. Both are converted with the unsigned `std::to_string(unsigned int)` overload.

`Na::ET::ProfileTrackingHelper::updateSequenceId` in `NaFusion10`, beginning at `0x4b4dc0`, receives a source curve, point, sorted set of intersection parameters, and a multimap of sketch-tag pointers. It obtains the point's curve parameter and locates its interval in the ordered intersection set. For an open curve, the fragment count is the intersection-parameter count minus one; for a periodic curve, it is the intersection count. No-split branches write `(1,1)`.

The native assertion strings are decisive: `newSeqId <= numInt` is referenced at `0x4b50a0`, and `newSeqId > 0` at `0x4b50c4`. The adjacent embedded source path ends in `DesignCapture/DataRef/Recipes/SketchRegionTrackerHelper.cpp`. At `0x4b50e0`, `stp w20,w21,[x23,#0x28]` stores the new ordinal and total count; `0x4b5124` propagates that pair to the other matching tag objects.

These are intended semantic invariants of valid produced values. The restore routines themselves read both uint32 values without checking the relationship. A semantic codec can reject malformed pairs, but must not replace real split pairs with `(1,1)` or impose the corpus's largest observed count as a format limit.

## Matching differs from pair equality

`split_sequence_id::isEqualTo` at `0xdc6a0` compares both fields. `split_sequence_id::match` at `0xdc6cc` instead accepts either unsplit pair `(1,1)`, matching sequence ordinals, or two final fragments where each ordinal equals its own total. For example, `(2,2)` and `(4,4)` are compatible final fragments even though their pairs differ. `sketch_tag_id::exactMatch` calls this compatibility function, so its method name must not be treated as proof of byte equality.

All 84 split tags satisfy the one-based invariant. The report includes an owning archive, entity, class, field path, and full tag for each nontrivial pair, as well as the complete list of affected archives.

Direction is also not a Boolean-only domain: the corpus contains 2,099 zeros, 2,964 ones, and 14 `UINT32_MAX` values. Native `compareDirection` at `0xdc8bc` explicitly treats `UINT32_MAX` in either operand as a wildcard; `exactMatch` repeats that logic at `0xde768–0xde784`. The qualified persisted direction values are therefore `0`, `1`, and `4294967295`.

The secondary uint64 is independent of both the split pair and role flags. `ProfileMatcher::getSketchCurvesFromRecipe` reads primary and secondary together for a `map<Ns::Geometry::Sketch::CurveTag,...>` lookup at `0x4b6114–0x4b6120`. This identifies its role as the second component of the source-curve key, but does not establish the allocator semantics of nonzero secondary IDs. The current corpus supports retaining the existing zero-only secondary profile.
